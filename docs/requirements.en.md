After the user starts companionship and states today's goal, the AI combines Google Calendar, saved materials, and currently enabled screens to offer quiet selection-based explanations, real-time voice discussion, proactive teaching, handwritten and illustrated notes, accountability reminders, progress tracking, and long-term memory. It uses evidence to analyze where reasoning began to diverge and which corrections worked, and supports independent progress with graduated hints and targeted practice. Unobserved processes and reasons the user has not expressed must remain unknown. Report supported paths and gaps under G7; do not require a manual screenshot or check-in for every step.

The complete original lecture-note flow is: the user stays on the original course/learning page and continues the lesson → uses this product's pen to take notes or work out problems live on the currently shared screen → preserves the user's original ink, source, contemporaneous screen, and video position → the AI adds only necessary diagrams, formulas, or short explanations while retaining the original independently → sends the notes to Notability under §7.5 and confirms the actual import state. ### 2.3 Adaptive teaching

- R14: Explanation depth depends jointly on current course needs, concept importance, the user's prior knowledge, and discussion history. Where shallow understanding is enough, explain only as much as needed; key concepts may receive fuller treatment.
- R15: Where course materials support it, connect the current concept to future uses and related knowledge, prioritizing what helps later understanding. When later materials have not been obtained, distinguish general subject relationships from this course's actual plan.
- R16: After an explanation, offer directions for deeper exploration with multiple selection, such as an intuition diagram, derivation, example, or future use. The user chooses freely; completing a quiz must not be required before continuing the lesson.
- R17: Automatically organize discussions into categorized small notes. When the same or related concepts recur, retrieve previous discussions and revisit them when appropriate. Retrieval should also work when the user remembers only vague clues. Automatically generated AI notes should contain helpful icons, drawings, formulas, and diagrams while remaining short; expand long explanations on demand. AI notes may stay in this app and need not all be pushed into Notability.
- R18: The user wants useful interactions inspired by mature teaching products and public educational resources. Reusing open-source tools, SDKs, APIs, and appropriately licensed prompts is allowed; implementing every underlying capability from scratch is not required.

### 2.4 Accountability, goals, and time

- R21: When the user changes learning goals, discuss whether the change makes sense in light of progress and the schedule. The AI may ask whether difficulty is prompting avoidance. Avoidance of difficulty is a hypothesis requiring confirmation, not an established psychological fact.

## 3. Architecture and default implementation approach

### 3.1 Capture and time alignment

R60 AUDIO-02–AUDIO-09/AUDIO-15 also constrain the transcription flow below: retain actual acoustic cues and raw/processed segment correspondence within the authorized processing window; never discard audio first and infer tone from text. Combining native-audio interpretation, faithful ASR, source/speaker evidence and synchronized views is a candidate architecture to measure, not a provider mandate. A text-only fallback discloses missing acoustic cues. Verify classroom microphone and actual playback audio, including headphones, separately; camera images, captions and input meters are not evidence that audio arrived. Preserve source language and oral exploration. AUDIO-13 closes the old recording-choice question; short verification-buffer settings remain engineering work, not default permanent recording.

Store real time, video playback position, capture time, and ingestion time separately. Distinguish the course audio track, user speech, and AI responses; never store the teacher's views as something the user said. Preserve source relationships through accelerated playback, scrubbing, crossing midnight, and backfilling after temporary disconnection.

In the background, transcribe authorized captured audio sentence by sentence, save key images at content changes and discussion moments, and associate caption/board regions with time. OCR alone loses geometric relationships, so retain necessary images. Capture or recognition failures leave explicit gaps; do not invent missing history.

Converting audio/video into text and key images loses information. During development, test whether details the user may ask about later can be recovered, and specify the short-term raw-media validation-buffer policy. The lack of a replay requirement does not justify retaining only a generic summary.

### 3.2 Independent memory layer

1. Source archive: complete interaction text, course transcripts, selections, key images, source identifiers, and event IDs. Append by default; corrections retain before/after relationships. Authorized deletion also covers derived indexes.
2. Derived material: small notes, concept relationships, course progress, explicit user goals, and understanding states awaiting confirmation. Every item links back to source events. Distinguish user words, course content, and AI inference.
3. Retrieval layer: combine keywords, semantics, course, time, and concept relationships. Find small notes first and read original conversations/images when needed. Expand the search when nothing is found; do not immediately conclude that the user never said it.
4. Current context: load only relevant material on each call. Compressing this layer does not modify the source archive. After changing models or embeddings, indexes can be rebuilt from the source archive.

Use PostgreSQL and object storage for the source archive. First implement rebuildable retrieval with keyword, vector, time, and source filters. Graphiti is the default candidate for concept/temporal relationship indexing, to be tested in the small comparison in Section 8. Add it only if it provides a measured benefit, and record the decision in an architecture decision record. Hindsight is a comparison candidate only; do not put several memory frameworks into production simultaneously. Regardless of the index choice, the framework must not exclusively own source archives or application identity.

### 3.3 Suggested small-note fields

`note_id`, course/chapter, concept, related concepts, the user's original question, useful explanation, key images, the user's understanding/misunderstanding at that time, unresolved questions, relevant future uses, source events, and creation/correction times.

A note must not equate having seen an explanation with mastery. If the user forgets again, the app may show the previous explanation that helped most and supplement it for the current question.

### 3.4 Preparation and live discussion

- Preparation prioritizes currently visible content and neighboring course materials actually obtained. Generate short explanations, identify concept relationships, and prefetch old notes.
- Live discussion references the current selection, relevant course materials, evidence of the user's knowledge, and recent conversation.
- Multi-select exploration directions distinguish course essentials, prerequisite repair, and optional interests, without adding a mandatory checklist for the user.

### 3.7 Model routing and cost control

Initial routing principles:

| Task | Initial processing approach | Escalation trigger |
| --- | --- | --- |
| Detecting screen changes, timing, deduplication, cache lookup | Deterministic programs or suitable device capabilities | Report unavailable data; do not have a large model guess |
| Clear captions / basic translation / retrieving and organizing materials | A less expensive model or specialized service, preserving the original text and locator | Ambiguous symbols, conflicting retrieval results, or technical wording that affects the conclusion |
| Batch preparation of short pre-lesson cards / note drafts | A model suited to the task, with sampling or review according to importance | New core concepts, derivations, or conflicts with the user's earlier understanding |
| User confusion, complex derivations, correcting understanding, cross-course planning | The user's selected flagship model with appropriate reasoning effort | Increase reasoning or split independent subtasks further according to problem complexity |
| Speech recognition, speech synthesis, immediate interruption | A dedicated real-time audio path | Clarify low-confidence transcription first; do not invent the user's question |

Task difficulty cannot be determined solely by labels such as “translation” or “research.” Mathematical translation and judgments about critical sources may also require a flagship model. Outputs from less expensive models should include sources; important tasks must not use their lossy summaries as the sole input. Model uncertainty, failed self-checks, and the user saying “that wasn't clear” (translated) all trigger escalation.

Prioritize content deduplication, incremental parsing, reuse of generated explanations, on-demand retrieval, and limited pregeneration. Use multiple Agents only for work that can be handled independently and demonstrably benefits, avoiding extensive mutual restatement that consumes tokens. Input caching and summaries do not delete long-term source archives.

The budget includes API costs for input/output, audio, vision, embeddings, image generation, failed retries, and similar usage. Reserve estimated costs before scheduling and settle them after each call; configure exchange rates and prices from information current at that time. Concurrent tasks must not each assume they have the entire remaining budget. Preserve capacity for live interaction first; explain available options at the limit rather than silently overspending.

Compare against an all-flagship approach on the same questions: correctness of critical explanations, correspondence to original materials, memory recall, time to the first useful response, number of user follow-up questions, and actual cost. Do not claim a savings percentage or guarantee equivalence before testing.

### 7.1 Initial setup and daily use

Device selection retains previous preferences and can be adjusted at any time; users need not reselect every time, and those preferences do not automatically enable capture on other devices. Apart from system-required actions, do not repeatedly collect links, course descriptions, or logins. The home screen shows only the current project, today's agenda, where to continue, and concise progress, rather than a long chat history. Make actual capture/model-receipt state, unavailability and stale gaps visible for each source; do not thereby enable other displays/devices or unauthorized microphones. Continuous context does not mean a paid call for every frame or constant spoken commentary: schedule processing by actual changes, user focus and the existing budget. Start grants neither premature solution disclosure nor actions in other apps.

Completing a valid circle highlights the user's focus within whole-screen context and automatically produces an appropriate contextual explanation/hint. Preserve the correspondence among full display, selection, obtainable ink, source/time/version and relevant conversation; do not replace the full screen with an isolated crop or require a second Ask button or typed question. Text/voice follow-ups are optional continuations. Circling is not permission for a full solution: check the current exploration scope and assistance level under R53/§7.7, clarifying only when needed. Stop, cancellation, revocation or source loss must fence subsequent queued/unsent requests and late responses; quota reset, reconnect or an old job must not automatically resume them.

Two evidence gates must pass separately: **(1) continuous whole-visible-display observation reaching the real AI**, independent of repeated selection; **(2) an original-screen cross-app region selector/pen reaching the same AI context**, with actual selected pixels and composite ink. Whole screen means the entire currently visible display, not browser maximization/fullscreen, DOM text or this App's canvas. Exercise leaving the browser for supported native apps, full-display coverage and selection alignment after window/scale/orientation changes. Separately verify actual permissions, full-display coverage, cross-app interaction and AI receipt on Windows and macOS. ### 7.2 Input modes

### 7.3 Tap-to-explain and proactive teaching

R60/A47–A49 live listening also apply: capturing and retaining teacher/user content is separate from deciding whether speech addresses the AI or authorizes a response. Quiet lecture mode still preserves authorized professor content. Use minimal clarification or the established talk control when source/addressee is unclear. Ordinary course viewing retains the proactive teaching below; while solving problems, R53's exploration constraints and the current request take precedence. Every teaching channel follows R57's persistent English-first preference; a temporary language override does not rewrite the default or source records.

Tap-to-explain/valid circling automatically presents a sufficient explanation grounded in the whole screen, focus, obtainable ink and relevant conversation under §7.1, with expandable original sources and no additional Ask press or typed-question prerequisite. Choose text, formulas, and diagrams according to prior knowledge and course use; offer multiple selectable directions for deeper exploration at the bottom. Show at most 4 directions by default and collapse the rest. Tap-to-explain and proactive teaching are silent by default. Text/voice follow-ups are optional; an explanation card appearing does not authorize reading it aloud.

Proactive teaching can be triggered by a related concept reappearing, an explicitly incorrect answer, repeated viewing, a prerequisite gap, or a user goal. First offer a small card: explain with another diagram, revisit an old note, or try a skippable question. Repeated viewing is only a clue; skipping does not mean inability. The initial default is not to repeat a proactive prompt for the same concept for at least 15 minutes after an unanswered prompt; a normal session should not accumulate multiple queued prompts. These parameters are adjustable.

Provide clearly visible talk/mute controls and current state. Every spoken AI response has corresponding floating captions, synchronized with the response/interruption and governed by the same disclosure limits. Unplayed queued content must not appear prematurely as already spoken. Default speech speed is 1.3× and is adjustable; interruption immediately stops old playback and its unplayed queue, while the new utterance determines whether long reasoning continues. Verify actual live microphone/system-playback support; a saved recording and upload are not prerequisites.

The toolbar and floating captions have visible drag affordances, move within the display work area and restore their position. Verify different DPI settings, movement between monitors, monitor removal/reconnection and reopening with controls still visible and operable within the work area. Dragging must not become a selection/question or alter originals/source anchors. Floating captions and movable controls are newly explicit interaction refinements from this user directive, not retroactive quotations from the old specification; record implementation and real-device acceptance separately.

Voice reminders about distraction or the end of a break use separate scheduling rules; do not interpret these as allowing proactive teaching to speak aloud at any time. The user still pauses the video themselves.

### 7.4 The user's handwritten notes and AI notes

Problem-solving originals must also preserve the operations, before/after revisions, and branches this App can actually obtain under R51–R52. If external notes provide only visual evidence, do not claim to have their complete undo history. AI-added images, titles, and review summaries are also subject to §7.7's disclosure rules.

There are three layers:

1. **User originals**: editable original strokes (currently supported desktop pen input, later Pencil), original layout, and versions. Save locally first, then synchronize in the background. Recognition results form an index and must not replace ink.
2. **Contemporaneous context**: original images / local crops, source links, course or self-study project, reliable video position/page number, and relevant discussion. Capture an anchor when writing starts; if writing continues after a substantial page change, add a new context segment without forcing the player to pause.
3. **AI additions**: necessary images, formulas, and a small amount of related explanation, independently hideable/deletable; do not rewrite the user's original handwriting. Formulas and screenshots come from actual material; additional illustrations are AI explanations and must not masquerade as diagrams drawn by the teacher.

Save automatic AI learning notes separately: by default, one title, at most 3 short points, and 1 necessary formula or image; show derivations and more examples only when expanded. This is an initial default to avoid verbosity, not a hard word-count cutoff. Full conversations remain stored in the background. After the user removes a type of addition, record the style preference rather than automatically adding it back next time.

This round confirms that both **content-anchored** and **screen-fixed** ink display modes must be provided. Both preserve the source/image at the time of writing; fixed display does not mean discarding the source. Verify scrolling, zooming, reflow, page changes, video changes, and problem switches. When reliable repositioning is impossible, preserve the original anchor and explain the state; do not assume arbitrary video-object tracking or native cross-App overlays are available. Display mode, content purpose, and external destination are independent dimensions: “fixed means scratch work, content-anchored means notes” (translated) is not a valid assumption. AI distinguishes learning notes from homework scratch work using actual context; mixed writing can be corrected, and only uncertainty warrants minimal clarification, without forcing classification of every stroke. Misclassification or deciding against export must not delete originals. Exact decisions and acceptance are in [Decision Record §3–4](requirements/intent-and-decisions.md#3-本轮已确认决定).

## 10. Application interfaces and background state machines

The following paths are this product's internal interface design, not existing external-provider APIs. Use versioned `/v1` paths and generate OpenAPI and client types. All writes verify user identity; supported idempotent operations use `Idempotency-Key`. Versioned writes use `base_revision`, and conflicts return 409 rather than overwriting.

| Interface | Input and result |
| --- | --- |
| `POST /v1/sources` | URL or connected-source identifier, optional project; returns persistent source_id, whether it already exists, and parsing status, and queues incremental processing |
| `POST /v1/connections/{provider}/start` | Required scopes and client callback information; returns the official authorization entry point; the callback validates state and saves credentials |
| `POST /v1/connections/{id}/sync` | Optional synchronization scope; returns job_id; reading status does not require starting the job again |
| `GET /v1/projects`, `GET /v1/projects/{id}/progress` | Returns courses, self-study projects, and work projects consistently; progress includes evidence and update time |
| `GET /v1/agenda` | Display time zone and time range; combines selected calendars, learning-project associations, and actual progress, explicitly retaining unknown associations |
| `POST /v1/sessions` | Today's goal/continue, project_ids; returns session_id, resume position, required permissions, and capabilities already available |
| `POST /v1/sessions/{id}/devices` | Device capabilities, pairing credentials, and enabled tracks; returns restricted, short-lived media permissions; the primary learner interaction-input role is unique; additional authorized source tracks are allowed through verified routes, not implied hardware concurrency |
| `POST /v1/events:batch` | Stable event_id, per-device sequence numbers, times, and sources; deduplicates and persists records, returning accepted sequence numbers; disconnected clients retransmit only unacknowledged portions |
| `POST /v1/explanations` | selection_id, project, knowledge-profile version, mode=silent; returns request_id, cache_hit, and an available short card or generation status |
| `WS /v1/sessions/{id}/events` | Ordered events: card_ready, answer_delta, note_updated, voice_state, job_state, capability_changed; reconnection may use last_event_id |

Media uses real-time transport and permission-controlled object uploads; do not put a large image for every frame into ordinary chat logs. Pairing tokens expire; long-lived credentials are not provided to third-party course pages.

Background-job states: `queued → running → completed`, with possible transitions to `waiting_for_auth / retry_scheduled / failed / cancelling / cancelled`. The initial default is at most 3 retries for transient failures, with exponential backoff. If an external write times out, query whether it took effect before retrying. Split autonomous web research into tasks based on explicit questions; every task has limits on time, calls, and cost. Incomplete tasks may resume from checkpoints, without endless loops.

Distinguish stop actions: ending companionship stops real-time capture and supervision; pausing reminders stops matching reminders; pausing autonomous preparation stops the corresponding workers; revoking a source stops reads/refreshes; deleting memory removes corresponding sources and derived copies, which old background jobs must not write back.
