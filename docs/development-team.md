**AI 学习伙伴：多 Agent 开发配置 v2**

> **历史方案，已被后续用户决定更新。** 本页保留初始分工与提示词的来历，以下旧模板不是现行系统指令，不能从这里重建当前状态或降低模型 effort。现行依据为[需求 v1.1](requirements.md)、[用户意图与决定](requirements/intent-and-decisions.md)、[TEAM](../TEAM.md)、[任务板](tasks.md)和[角色目录](team-directory.json)中的身份／工作区记录；目录内历史 effort 由后来的明确用户设置优先。P0 已获授权且已开发、集成和验证，具体状态见任务板。

用户已明确允许使用多个 agent。本版将上一版的双线方案扩展为五个固定职责，加一个按需启动的独立验收角色。模型仍主要使用 GPT-6 Astra 和 Opus 5.5；同一模型可承担多个独立会话。

历史配置依据是 v1.0 的 R01–R50、A01–A29、G1–G6、P0–P4；“应用功能开发尚未启动”仅描述设置验收当时，已被用户后续启动 P0 的决定替代。现行 v1.1 保留原目标，并采用 R51–R59、A30–A46、G7 及最新具名验证／决定。原六角色、工作区与双向连接已验证；新的角色登记以正常交接和实际路由为准，不由本文推断。Windows、iPad、iPhone 与尚无确认 Mac/Xcode 路径的环境限制仍按实测记录，愿意购买 Mac 不等于采购指令。

| 03 学习与记忆 | Astra | 检索与 G6 对照、解释、掌握证据、模型适配、教学策略与质量评测 | services/learning、services/worker/learning、tests/fixtures/memory、tests/evals |
| 04 iPad 原生体验 | Opus 5.5 | SwiftUI、PencilKit、原生采集与音频、离线笔迹、应用生命周期 | apps/ios 及对应测试、原生平台验证记录 |
| 05 Safari 与桌面端 | Opus 5.5 | 原课程页面圈选与卡片、手指导航、iframe／全屏；后期 Windows 同伴 | apps/safari-extension、后期 apps/windows 及对应测试 |
| 06 独立验收 | 按被审任务选择另一模型 | 固定提交的独立复现、边界测试、集成回归与证据检查 | tests/e2e、独立验收记录；生产修复单独分派 |

目录是工作分界建议，实施时可调整名称。02 与 03 分开，是为了让基础存储、同步、连接器的开发，与检索和教学质量试验同时推进。04 与 05 分开，是因为原生 App 与网页扩展的输入、权限和验证路径不同。

总工负责公共契约和集成决策，数据库迁移由 02 单一作者维护。03 需要存储结构时提交变更请求，不能另建一套用户身份或原始记忆库。04 和 05 依据同一 native bridge 契约实现各自一端，分别验证。

模型分配是初始试验方案，依据模块边界安排；不宣称 Astra 天生更擅长数据库或 Opus 天生更擅长 Swift。第一轮以验收耗时、缺陷、返工和实际用量决定调整。OpenAI Docs 特别强调为 Astra 明确委派时机和方式。[Astra 官方指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)

**启动数量与时机**

六个角色不需要同时持续生成。建议初期同时运行三个任务，接口稳定后通常运行三至四个；有足够独立任务、环境和账号用量时再升到四至五个。这里的数量是本项目初始调度建议，不是 AgentsDock 的产品上限。

| 阶段 | 并行工作 | 完成后如何推进 |
| --- | --- | --- |
| 第一次启动 | 01 做最小契约／骨架；05 做网页输入探针；04 做有边界的平台验证准备 | 一版契约提交后即可交给数据与学习线，不等待整套设计全部完成 |
| 固定样例可用 | 02 做源档案／同步；03 做检索基线与解释评测；05 做已可验证的网页交互 | 01 按提交批次集成；06 检查已经可运行的成果 |
| Mac 构建与 iPad 安装通路可用 | 04 做原生真机验证；其他独立任务继续 | 原生与网页体验按共同事件契约接入服务端 |
| 首次真实课程闭环后 | 根据实际排队情况安排三至五个任务 | 接口稳定、无需互相等待的模块才继续扩展并发 |

没有 Mac 时，04 完成能力资料核查、最小原型设计和明确的环境清单后结束该任务；不要持续堆积未编译 Swift。可将空出的执行名额用于 02、03 或独立验收。Safari 纯网页扩展已有无需 Mac 的官方打包路径，适用条件仍须核实；它不等于完整原生 App 的打包路线。[Apple Safari 扩展](https://developer.apple.com/safari/extensions/)、[原生通信教程](https://developer.apple.com/videos/play/wwdc2026/216/)

官方多 agent 实践也建议优先并行独立模块，并明确协调开销和用量随人数增加；依赖强的任务不应硬拆。[Claude Code 团队实践](https://code.claude.com/docs/en/agent-teams)

**各自工作目录与协作规则**

应用已单独建仓库，实际目录如下：

```text
/home/agentsdock/Projects/learning-companion/
  repo/                  总工管理的集成工作目录
  wt-platform/           iPad 原生开发分支
  wt-web/                Safari／Windows 开发分支
  wt-backend/            数据与后台开发分支
  wt-learning/           学习与记忆开发分支
  wt-review/             独立验收，固定到待审提交
```

AgentsDock 各聊天的 Session → Working directory 指向各自目录，System prompt 使用下方角色说明。每人使用不同 Git worktree 和分支；测试端口及数据库命名空间也分开。01 是唯一集成人；应用代码的责任方在自己的分支修复后再提交。

公共协议、根依赖和 CI 由 01 修改；数据库迁移由 02 修改；04 维护原生工程配置和 entitlement；05 不直接修改原生工程。其他角色通过明确的变更请求提出需求。

公共规格、契约和规则用 Git 提交同步。新会话读取同一基线提交，再开始任务；worktree 不会自动看到另一分支的最新文档。未授权修改的文件属于任务边界，这种约定本身不等于操作系统权限隔离。

在 AgentsDock 用 @ 从列表选择实际聊天，交接下面的任务卡。角色使用明确名称而不是“让另一个 AI 看看”。先验证一次实际接收与回传，再扩大任务量。AgentsDock 官方描述的是跨聊天的任务交流；自动排队、合并和完成判断仍需落实并验证，不能仅凭写了系统提示就宣称已全自动。[AgentsDock 功能说明](https://agentsdock.net/features.html)

**全体共用的简短规则**

```text
依据指定版本的需求、任务卡和公共契约开展工作，维护对应 R/A/G 编号。
只修改分配目录；发现公共接口、依赖或迁移需要变化时向责任人提出具体请求。
在自己的 worktree 完成实现和相关验证，返回提交 ID、证据、未验证项与下一步。
区分已实现、已编译、已自动测试、已真实接通、已真机验证；不得相互冒充。
保存原始事件、来源与用户笔迹；摘要和索引不能替换它们。
本地实现、相关测试和修复连续推进；遇到外部条件阻塞时记录原因，推进独立任务。
不重复实现已交给其他角色的任务；不擅自新增长期运行的 agent。
```

以上为团队任务规则。实际权限随开发环境与用户授权配置。将共用规则放在团队说明中，由 AGENTS.md／CLAUDE.md 引用；完整需求另存，避免给每个 System prompt 填入整份规格。

**历史角色补充提示词（仅背景，不覆盖现行 docs/roles 与 TEAM）**

01 总工与集成：

```text
你是技术负责人和集成人。负责最小公共契约、任务依赖、根配置和需求追踪。
按可独立交付的模块委派任务，说明基线、可写路径、验收和证据。保留清晰的任务状态与负责人。
有独立任务就并行，无独立任务时推进接口决策或集成；不要重复实现已委派的功能。
审阅并合入可运行提交，检查集成版本。把架构分歧转成有限的小原型或复现测试。
```

02 数据与后台：

```text
你负责源档案、事件同步、身份、数据库迁移、预算账本、队列与来源连接器。
确保事件幂等、乱序确认正确、原话和关键图可追溯；离线历史上传不重新开启实时监督。
维护唯一原始数据模型；索引更新或日历重建不得删除学习记录。
验证并发预留、取消、撤权、删除与后台旧任务竞争；对外部写入结果未知的情况先对账。
```

03 学习与记忆：

```text
你负责检索、解释、概念与掌握证据、模型适配和教学质量评测。
通过公共接口读取源档案；只维护可重建的派生资料与索引，不改写原始记录。
先用相同固定语料比较混合检索基线与 Graphiti，保留失败例，再依据结果选择。
区分看过、计划过、自述理解与独立应用。教学材料 English-first，保留课程术语，难点可加简短中文提示。
交付可复现实验、正确来源证据、错误类型、延迟和用量；不以另一模型的赞同作为正确性证明。
```

04 iPad 原生体验：

```text
你负责 apps/ios 的界面、PencilKit、离线笔迹、原生媒体和生命周期。
优先验证原页面学习所需的公开平台能力；先检测实际设备与系统。
区分 Pencil 与手指，原笔迹与 AI 补充分层，选区绑定固定画面。
记录真实音轨、麦克风、切后台、系统停止与显式结束行为。无编译或真机通路时清楚标记，完成有限准备后交回任务。
```

05 Safari 与桌面端：

```text
你负责 Safari 原课程页面的圈选、静音卡片和正常手指导航，后续负责 Windows 同伴。
逐项验证授权页面、跨域 iframe、全屏视频、字幕和板书选区，记录实际支持范围。
与原生端通过共同 bridge 和事件契约协作，不修改原生工程配置。
桌面浏览器的测试不计作 iPad Safari／Pencil 真机通过；对不支持场景实现需求已经接受的备选。
```

06 独立验收：

```text
你负责指定提交的独立验收。自行阅读差异、复现问题并运行相关检查。
优先检查来源混淆、旧帧、选区漂移、笔迹丢失、重传、更正与删除、预算竞争和停止行为。
报告复现步骤、预期／实际、严重程度和证据；未测试与失败分开。
修复交回责任人，除非任务明确分配给你。最后检查集成提交，不用旧分支结果宣称最终通过。
```

**每次委派的任务卡**

```text
任务 ID / 负责人：
目标及 R、A、G 编号：
基线提交 / 契约版本：
可写路径：
依赖及公共文件负责人：
完成标准 / 验证命令 / 真机步骤：
交付：提交 ID、测试结果、证据、未验证项。
遇到阻塞：记录具体原因和所需输入，继续独立工作。
```

先统一事件信封、选区锚点、同步确认、笔记版本、授权与过期状态、费用预留七类契约。第一项集成成果仍为：真实课程圈选 → 静音解释 → 保存 note → 关闭重开 → 找回同一来源。语音、日历和其他 P1 条件全部验证后才算 P1 完成。

源档案、最小检索、预算预留和基本日历增量同步保持前移到 P0/P1；三设备、自主备课、完整教学与工作 Agent 按原阶段推进。扩大团队不扩大采购权限，也不把尚未测量的能力写成已完成。

**思考强度与用量**

原建议“架构 XHigh、常规 High、简单 Medium”已被用户后续决定替代，不得据此降档。现行开发团队保持 GPT-6 Astra `ultra`、Claude `ultracode`；PONYTAIL LITE 是按 TEAM 项目覆盖应用的实现风格，不是 reasoning effort。成品 R04/R42 仍可采用有实际质量对照的成本路由，两者分别管理。记录验收耗时、返工、缺陷、集成等待和实际用量，不承诺未经本项目测量的节省比例。

同一供应商的多个聊天使用对应账户的额度；聊天数量不增加订阅权益。成品 App 的人民币 1,000 元月度 API 预算，与开发过程的订阅用量分别记录。只有存在独立任务、可用环境和可验证收益时才扩大并发。

用户日常主要与 01 交流。初始有限交接检查已经完成；后续按已授权 P0 持续审查、集成、验证和分派，发送一轮消息不等于项目停止。历史额度错误与当前实际交付分别记录，不能用旧 setup-only 或未读回执推定拒绝开发。
