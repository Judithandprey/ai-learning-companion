## Actual call-path fit

Read existing `services/api/{app,auth,control,capture,display_sources,original_artifacts}.py` and released contract dependencies. New wrappers reuse source identity and the existing original/process/frame contracts without adding an archive or auth model. Registration contains no user, producer, grant, creation-time or capability assertion. The README correctly requires a current trusted producer/grant resolution inside the actor transaction; current `Principal` alone supplies neither capability nor producer authority.

Creation and identical display registration replay, and display original PUT including exact byte replay, still require current live capture authority. Historical source/original GETs remain distinct and recheck present account/source access, tombstones, retained binding and exact bytes. Withdrawal/stop does not itself fabricate a live claim or erase accessible history. Current frameless-display and unresolved-attempt limitations are explicit rather than silently bypassed.

Frame wrappers exhaust unique supplied frame IDs and compose released record/frame/original relations; foreign or malformed identities, inconsistent metadata, original bytes and extra authority fields reject. Unknown actor/state and historical timestamps remain unchanged; metadata consistency does not prove pixels, current app identity, coverage or AI input. Bytes committed, process ACK, model input, displayed help and destination import stay distinct.

HTTP replay is deliberately stricter than the current internal frame-map cache: full wrapper and ordered arrays participate; owner/method/full path/key and current fences must share the actual transaction. The README explicitly retains this Backend implementation prerequisite and forbids a separate check-then-commit cache. Request media/header/query/path parsing, capability negotiation, status mapping and fresh transactional authority remain future adapter obligations, not implemented by the pure validator.

Generated JSON Schema, TypeScript and OpenAPI agree on five operations, versions, Bearer protection, cumulative and source-conditional scopes/capabilities, body ceilings and error families. Existing 0.1.0–0.2.3 generated bytes are unchanged. Root check/TypeScript includes are additive. The separate generated review is `/tmp/capture-ingress-generated-review.md`.

## Observed issue and correction

Initial `FrameBatchRequest` validation called `validate_capture_frame` with the complete batch for every record, revalidating all peers. A single valid synthetic 100-record/100-frame case (116,564 JSON bytes; no byte callback) took **2.986248 s**; released ProcessBatch alone took **0.029757 s**, and one-record wrapper **0.001923 s**.

The author corrected only the new wrapper: complete batch semantic validation remains first, then unchanged released binding validation receives `{**batch, 'records': [record]}`. Originals/output are not modified. Same independent probe now gives **0.138415 s** for 100 records, **0.028070 s** for the full ProcessBatch and **0.001953 s** for one record. These are individual local timings, not a latency benchmark or device promise. The new regression rejects whole-batch forward causality and conflicting immutable artifact references and checks input preservation. No old schema/validator rewrite was needed.
