## Authority, preservation and current scope

The user explicitly changed delivery priority to the complete required experience
on **both Windows and macOS first**, deferring native iPad/phone delivery. This is
not a reduction to P0/P1, an import-based browser preview or Windows-only delivery.
All R01–R60/A01–A49/G1–G7, V/INTENT/AUDIO/AVTEST goals remain; native/mobile cases,
source and historical evidence remain with their later stage. Sidecar is a later
Mac-app candidate, not a core desktop prerequisite or arbitrary native-iPad overlay.

The main source/English requirements, current decisions, process/audio detail,
verification/traceability, task sequencing and role entrances are updated together.
Existing P3-02 becomes later cross-surface hardening; it no longer delays first
Windows/macOS original-screen ink. Web owns Windows, native `ios` owns macOS;
all seven identities/routes/worktrees/models/efforts/permissions remain unchanged.

The normal user preview/database (`lc_desktop_preview`, ports4173/8174), its
identities/token files and the isolated Paperclip trial are untouched. Existing
provider defaults remain disabled. No paid service, hardware, new account or
runtime permission change is part of this transition.

## Bounded current deliveries

They must produce actual original-display observations and clean Stop behavior;
a local screenshot, mock receipt or compile result cannot pass either whole core
gate. Full ink/audio/learning/destination requirements remain separately open.

lead-owned P0-08 boundary, using existing storage/auth/control/capture components;
no public provisioning endpoint or default producer. Learning receives one bounded
observation-window preparation implementation over the existing source archive;
no synthetic vision understanding or disclosure grant. Support gets one explicitly
delegated desktop CI/package-path patch. QA's next assignment waits for the exact
runnable Windows candidate and uses independent actual behavior evidence.

  and authorized usage path not supplied. No new paid activation is authorized.
- Trusted runtime bootstrap: currently unimplemented; now a bounded delegated
  source task, not accepted functionality or a production-login substitute.
- Interactive Mac: unconfirmed. A later authorized session on a supported Mac
  must exercise actual permission UI, capture, native-app input/audio and Stop.
  Hosted macOS build/test output cannot establish those capabilities.
- Mobile signing/device/Pencil/Sidecar: explicitly deferred with original goals
  intact; not reasons to block independent desktop work.
