# Managed subscription ASK: bounded interface review

Read-only review of `ff163a6ebbb9d974055e23ae97d0359e17cecef4`, ADR 0003 and the existing Windows ASK / main provenance / Learning PNG-validation path. Requirements read: R38, §3.8, §7.1–7.3, §7.7, current decisions and relevant original-goal case. In-progress Lead requirement edits were preserved. PONYTAIL LITE: reuse the existing crop, original-byte hash, PNG validator and lifecycle patterns; no new service/framework proposed. No Codex/auth files, network, inference, display or services used. This is interface review, not implementation acceptance.

## Resolve before interface adoption

1. **Freeze the connection and completion envelopes (Lead → Backend/Web).** ADR lines 49–55 prescribe semantics but omit exact result/event field shapes for `connection/read`, `connection/login/start` and `connection/login/completed`; similarly `provenance` and the generated-assistance label in the Learning seam have no exact object shape. These are directly consumed by independently implementing owners. Agree one sanitized JSON example for unauthenticated/authenticated state, model image-capability unavailable versus false, successful/pending/failed login, and bound answer provenance. Keep auth/login data out of persisted evidence. This prevents property-name/nullability drift without introducing a public contract or generic adapter framework.

2. **Specify rectangle coordinate spaces and cross-field checks (Lead → Learning/Web).** Existing `apps/windows/src/shared/samples.ts:79–91` maps *display-local* DIP (origin 0,0) to full-frame pixel coordinates, while `display.bounds.x/y` in main are virtual-desktop positions and may be negative. ADR lines 82–97 do not distinguish these origins or whether `region_px` must fit the full frame or the already cropped image. Explicitly define `region_dip` as local DIP bounded by display width/height, `region_px` as full-frame-local integer pixels, and `image.width/height == region_px.width/height`. Use the existing floor/ceil/clamp mapping based on actual `frame_width/height`, not `scale_factor` alone. Define edge clipping consistently before validation. Otherwise valid secondary-display/non-unit-scale selections can be rejected or incorrectly attributed by different implementations.

## Required implementation joins; do not copy current local-card behavior unchanged

3. **Separate request lifetime from input-mode lifetime (Web, Backend).** Current `finishAsk` (`overlay.ts:697–732`) checks `mode === ASK` only after encoding and restores WRITE/NAV only at the end; current Cancel is hidden outside ASK and card Close only hides the card (`845–860`, `875`). Awaiting real inference before `ask_finished` would hold the selection input layer throughout model latency; restoring first and retaining the current guard would discard every legitimate answer. Maintain one independent pending request/selection token, restore prior mode on confirmed selection, and expose cancellation while the response is pending. Close/reselection, relevant scope/permission changes, Stop and renderer failure must invalidate that token and suppress late display. `endCapture` sets `ended` without changing ASK mode (`178–185`), so explicitly check the ended/session fence after every asynchronous preparation boundary. Main's synchronous `end()` latch (`main.ts:218–225`) is the right existing place to fence and cancel before save cleanup. The JSONL reader must process cancel/stop while `ask/start` is outstanding; a serial reader awaiting inference cannot satisfy ADR's cancellation guarantee.

4. **Hash the selected immutable ink bytes, not the later saved document (Web → Learning).** `finishAsk` pins `inkDoc = doc` before crop encoding. Context attachment can later replace the document without changing the visible ink revision (`overlay.ts:581–611`), and `save()` waits for contexts then saves the newest `doc` (`627–631`). Therefore awaiting save and reading the current/saved document to fill `ink_sha256` can bind a different original from the one composed. Serialize and retain the exact selected `inkDoc` with its crop before asynchronous work, as the existing whole-frame retention already does (`main.ts:578–601`). Hash those exact bytes; preserve pending/unknown context status. Do not substitute a current ink document merely because its revision matches. Keep request question/assistance and immutable provenance available for final presentation checks; §7.7 requires current permission/scope checks beyond model prompting.

The existing Learning `_png_status` already provides bounded RGB/RGBA 8-bit, noninterlaced PNG validation, CRCs, dimension and decompression limits (`services/learning/images.py:16–88`); reuse it and expose unsupported variants honestly. The existing crop fixes pixels before async encoding and draws uncertain ink as dashed, so no replacement capture architecture is needed.

Independent acceptance should target one negative-origin/scaled-display envelope, a save/context mutation during preparation, cancel before submission, cancel during an outstanding turn, and Stop followed by delayed completion/new submission. These focused controls remain separate from the required real randomized image-bearing Windows response.
