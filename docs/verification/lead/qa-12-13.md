## Actual reproduction and fix

Independent QA delivery `4e0dff99e75e0c162e76ddaedc6907e854180edf` was read and
cherry-picked as `6673a3d`. Before the fix, running
`.venv/bin/python -m pytest -q tests/e2e/test_p0_06a_contracts.py -k deeply_nested --runxfail`
failed both tests: a 3000-level object raised `RecursionError` in direct contract
validation and authenticated in-process `POST /v1/sources`, rather than producing
`ValidationError` / HTTP 422.

The integer scan now uses an explicit stack after the finite-JSON check; the
encoder's recursion-limit failure becomes a validation error. The independent
deep-payload fixture now constructs its Python object iteratively, so its setup
does not depend on the Python version's JSON decoder nesting limit. Raw HTTP input
remains a separate regression. A further test covers deeply nested arrays inside
an existing scalar field, not just a dictionary in an unknown field.

Timezone checking only converts `ENAMETOOLONG` to invalid input; permission/I/O
errors propagate. Existing malformed-zone handling and valid examples remain.
New regression tests inject `EACCES` and `EIO` rather than depending on host file
permissions. Runtime/programming errors are not caught as invalid user input.

[Side-by-side probes](qa-12-13/probes.json) compare the committed pre-fix validator
with the working fix: depths 996/3000/20000 change from recursion crash to rejection;
900 stays rejected; timezone permission/I/O faults stop being mislabeled; all 15
core/HTTP examples pass. These are local Python 3.14.4 results, not deployed service
or real-database evidence.
