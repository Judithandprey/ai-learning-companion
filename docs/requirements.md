# 个人 AI 学习伙伴：Codex 开发规格 v1.0

定稿日期：2026-09-27，America/Los_Angeles。状态：完成四轮需求访谈，可交给 Codex 开始实施。本文是项目规格，不是已实现或真机验收报告。系统版本、账号权益和受限制的平台接口由实施时检测，不再以反复询问产品意图作为开工前提。

**给 Codex：**先执行第 8 节的能力验证，再按第 12 节阶段交付。R01–R50 是用户需求；第 3、7–12 节的数值、技术栈和交互细节是为实施选定的初始默认值，可依据测试改进，但不得删去用户核心需求、伪造已接通能力，或把原页面陪学替换成只有上传 PDF 的聊天产品。平台不支持的功能使用本文明确的备选流程并报告实际支持范围。

## 1. 产品目标与交付目标

让用户继续在 iPad 原有课程网站、视频 App、笔记 App 中学习，也支持没有固定课程的自学计划。启动陪伴并说出今天目标后，AI 结合 Google Calendar、已保存材料及当前启用的屏幕，提供安静点读、实时语音讨论、主动教学、手写与图文笔记、督促、进度与长期记忆。体验上是持续认识同一个人的学习伙伴，模型切换不重置关系、目标或历史。

产品首先服务用户个人，架构保留账户隔离；不要求先做商业化、公开注册、计费销售或社交系统。交付应包含可运行客户端与服务、配置说明、真实能力矩阵、与本规格相连的验收证据。不要因某个外部笔记 App 缺少接口而搁置核心体验。

## 2. 已确认需求

### 2.1 使用环境与启动

- R01：iPad 是主设备，用户偏好在 iPad 学习，不应要求改用电脑。设备自述为“iPad 2025”、Apple Pencil Pro、iPhone、Windows 电脑；常用 Notability 存自己的笔记。用户同时使用 Canvas 原生 App 与 Safari。“iPad 2025”不推定为具体 Pro/Air 型号或某个系统版本，应用首次运行自动检测。
- R02：用户希望每天只需打开 App、说出学习目标。课程不要求逐次搬运、导入、截图上传。允许首次连接 bCourses，正常情况下自动维持连接；需要其他资料时，AI 可请求用户连接 Ed、Gradescope 等来源。不能把持续登录承诺成授权永不失效。
- R03：留在原页面非常重要；确实无法实现时，用户接受以可用性优先的备选方案。必须先验证平台能力，再确定备选流程，不能默认把产品改为独立 PDF 阅读器。
- R04：用户可选择模型，偏爱 GPT-6 Astra Ultra 一类旗舰体验。记录、个人资料、笔记和进度由本应用统一持有，不绑定模型供应商或单个聊天线程。可自动调度更便宜的模型处理合适任务，优先保持教学和交互质量。
- R05：整体范围包括工作模式：与已有 Agent 一边工作一边学习，保留其工具与任务上下文。按第 12 节阶段接入，默认先适配 Windows 上可用的官方 Codex 入口，随后 Claude Code；用户不需重新回答 Agent 选型才启动核心开发。

### 2.2 指选、解释与声音

- R06：用户可指选词语、句子、公式和图的一部分；字幕和板书也属于可解释内容，不以它们是否为可选中的网页文本为前提。
- R07：视觉识别应处理板书、图示与公式，并保留原始局部画面作为依据；模糊符号不能只留下一个未经验证的 OCR 结果。
- R08：正常点击、滚动、书写、拖动进度条不能误触发解释。使用图标按钮区分 Pencil 的提问与笔记模式；Pencil 模式下，手指始终用于正常操作屏幕。未连接 Pencil 时，显式点图标进入手指圈选模式。图标跨原生 App 显示的能力不能未经验证就承诺。
- R09：点击／圈选默认安静展示解释，不自动朗读；用户主动向 AI 开口提问时进入语音讨论。语速偏快，可打断；实施初始值和语音识别失败时的入口见第 7.3 节。
- R10：用户自行暂停课程。首版需求不包含自动控制所有课程播放器的播放／暂停。字幕或板书选区绑定用户指选当时的画面，不能因视频继续播放而改指其他内容。
- R11：解释可包含文字、公式、图示；合适时可以增加可操作的数学演示。具体形式服务当前疑问，不要求每次全部出现。
- R12：系统提前预测可能点选的概念并准备内容，以缩短等待。预生成结果需匹配课程、具体出现位置及个人理解状态；不能为了响应快而显示不相干旧答案。
- R13：未命中预生成内容时可即时生成，不能假称已准备。缓存命中率、首个有效解释延迟、完整解释延迟需分别测量，初始验收目标见第 11 节。

### 2.3 教学适配

- R14：解释深度由当前课程需求、概念重要性、用户已有知识与讨论历史共同决定。只需浅理解时讲到够用；关键概念允许更完整展开。
- R15：有课程资料依据时，把当前概念与后续用途、其他相关知识点联系起来，优先讲对后面理解有用的部分。未取得后续材料时区分一般学科关系与本课实际安排。
- R16：解释结束后给可多选的深入方向，例如直觉图、推导、例子、后续用途。用户自由选择，不能强制完成测验才继续看课。
- R17：讨论自动整理成分类小 note；以后遇到同一或相关概念时，检索此前讨论并适时回顾。用户只记得模糊线索时也应能找回。AI 自动图文笔记包含有助理解的图标、绘画、公式与图示，保持简短；长解释按需展开。AI 笔记可以留在本 App，不强制灌入 Notability。
- R18：用户希望参考成熟教学产品和公开教学资源的好用交互；允许复用开源工具、SDK、API 与有合适许可证的提示词，不要求从零实现所有底层能力。

### 2.4 督促、目标与时间

- R19：学习期间，AI 可观察用户是否偏离当前目标并主动语音提醒。应结合内容判断查阅是否相关，不以离开课程 App 本身就认定走神。
- R20：用户说休息十分钟时，结合已学习时长与会话情况回应，记录真实结束时间，到点提醒；计时不能依赖模型凭印象估算。
- R21：用户切换学习目标时，结合进度和日程讨论是否合理，也可以询问是否因困难而回避。畏难属于待核实推断，不能写成确定心理事实。
- R22：用户手动退出可以结束实时监督。退出后可通过 App、SMS 或可实现的其他渠道督促；用户把提醒时机与强度交给 AI 按事项紧迫性、重要性决定。微信、抖音是希望探索的渠道，不是已确认可用接口。此条是产品设计需求，不授权当前助手现在发送消息。
- R23：用户偏好认真、能劝说且耐心的督促；可依据实际情况严格提醒，也会哄用户推进。最终措辞需要用样例校准，不把固定羞辱句当通用模板。
- R24：随口提到的长期愿望要保存，例如补线性代数；下次一起学习时主动提起，并结合实际需要评估优先级。对此类模糊长期目标，不额外频繁发通知。
- R25：用户持续回避确有必要的学习时，可以在后续学习会话中多次耐心提醒。提醒历史要记住，避免每次当作新目标重问。
- R26：平台允许时，希望增加所选干扰 App 的限制；强制跳回课程属于能力待验证项。首版不能把未经验证的系统控制写为既有能力。

### 2.5 长期记忆与前台显示

- R27：完整用户／助手文字对话在后台保留并可检索，前台不展示长聊天流水。这里保存的是实际交互记录，不要求保存或展示模型内部思维过程。
- R28：讨论画面和有效解释形成小 note，自动分类；用户提起时能快速找回。课程进度要可见，目标与学习记录默认由伙伴在后台管理。
- R29：不需要连续音视频回放。需要保留能回答“老师讲那句话时是什么概念、我当时说了什么”的文字、画面和时间关系。
- R30：不因后来学得多或当前模型上下文变长，就用缩短摘要覆盖旧文字和关键画面。摘要只能是补充索引。用户明确更正或删除的行为另行处理。
- R31：产品不应设置一个很小的固定文字记忆上限；实际容量、存储成本和服务边界要透明，不能宣称物理上无限或百分之百不忘。
- R32：跨课程、跨天、换模型后仍属于同一伙伴。保存与检索不能仅依赖供应商聊天历史。

### 2.6 自主运行、多设备与预算

- R33：用户不在线时，伙伴可以在后台读取已经授权的课程、预习、准备解释和笔记，也可搜索公开网络资料。它应主动发现缺少的资料并提出连接需求，不要求用户逐步指挥。
- R34：用户所称“真正的 AGI”体现为期望独立判断、持续学习与执行。工程验收采用可观察的计划、执行、核查、调整和记忆行为，不用“实现 AGI”作为不可检验的交付结论。
- R35：允许用户选择同时共享 iPad、手机、电脑的屏幕，例如 iPad 播课程、手机查资料、电脑工作。所有启用的设备应属于同一会话，AI 能把跨屏活动联系起来。
- R36：每台设备的屏幕共享必须可分别启停，不能因其中一台设备加入就默认采集其他设备。首批为 iPad、iPhone、Windows；具体 OS 版本由客户端检测。
- R37：用户愿意在确有必要时购买性能更强的服务器；这不是当前购买指令。先验证与测量资源需求，不以购买硬件代替解决客户端能力限制。
- R38：用户自述已有 OpenAI 的“20X”订阅、Claude Max、Gemini Pro。优先利用官方允许使用的已购权益；不足时可走 API。未实际核实账户方案、权益、使用量或余额。
- R39：用户接受每月额外约人民币 1,000 元 API 费用；可进一步考虑升级订阅，但未授权现在购买。初始设计把 1,000 元设为 API 月度预算上限，后续升级需用户明确选择。服务器、短信等其他费用单列，不暗中侵占或扩大预算。
- R40：用户没有确定每日用量，可能长时间保持陪伴。设计必须区分“会话在线”和“持续调用昂贵模型”，通过内容变化、查询与实际需要触发处理。
- R41：用户允许 AI 反对临时放弃、追问拖延原因并独立提出更合适的行动。明确停止、暂停提醒和撤回授权仍应生效；不能把“为了用户好”解释为无限扩大控制范围。
- R42：省成本方案的目标是维持接近全旗舰的主观体验。不能无测试保证等价；不得隐藏模型降级导致的能力变化，或用低质量压缩删除长期源记忆。

### 2.7 自学来源、日历、手写和主动教学

- R43：课程可以来自独立网站；学习目标也可以是机器人／AI 等自学计划，不要求存在 Canvas 课程、老师或统一教学大纲。
- R44：用户发一次链接后，持久保存、归类并在以后继续使用，不能每次启动要求重发。链接与材料版本、学习进度及旧讨论相连。
- R45：Google Calendar 是核心来源。要利用其中已有的 AI 学习计划、安排与截止时间理解今天该学什么，并结合真实学习进度调整建议。
- R46：用户可在支持的学习画面上用 Pencil 写自己的笔记；自动保存原笔迹，并关联书写时的课程／自学项目、画面、视频位置和讨论。
- R47：对用户手写笔记只补充必要的图、公式、课程截图局部或简短关联说明，避免冗长。优先从实际课程画面提取有用图示；用户笔迹不可被 AI 改写替代。
- R48：用户希望自己的手写笔记能存到 Notability；若无法自动写入，可采用其他笔记软件。用户提到“Google note”未明确具体产品，不能直接假设已有 Google Keep 企业 API 权限。首选保留应用内可编辑原稿，按第 7 节支持外部归档。
- R49：允许主动教学、可跳过的小问题和理解检查。伙伴应循循善诱、能讨论、有亲近感，主动跟踪学习进程与掌握程度，而不只是等用户提问。
- R50：进度、掌握程度和日程分别存储。看过／计划过／用户说懂了／能独立应用是不同证据；不能用观看时长或日历事件结束直接判定掌握。

## 3. 架构与实现默认方案

### 3.1 采集与时间对齐

把真实时间、视频播放位置、采集时间、入库时间分别保存。区分课程音轨、用户讲话和 AI 回答，不能把老师观点存成用户说过的话。倍速、拖动进度条、跨午夜、暂时离线后补传均保持来源关系。

后台把授权采集的声音转为逐句文字，把内容变化和讨论时刻的画面保存为关键图，并建立字幕／板书区域与时间对应。仅存 OCR 会丢失几何关系，需保留必要图像。采集或识别失败留下明确缺口；不能编造未取得的历史。

音视频转文字与关键图存在信息损失。开发阶段需比较“用户希望以后问的细节”是否能被恢复，并明确短期原始媒体校验缓冲策略。不能以用户不需要回放为理由，只保留一段泛泛摘要。

### 3.2 独立记忆层

1. 源档案：完整交互文字、课程转写、选区、关键画面、来源与事件编号。默认新增记录；更正保留前后关系。授权删除需覆盖派生索引。
2. 派生资料：小 note、概念联系、课程进度、用户明确目标、待确认理解状态。每一条可回到源事件；区分用户原话、课程内容和 AI 推断。
3. 检索层：关键词、语义、课程、时间与概念关联共同检索。先找小 note，需要时读原对话与画面；没找到时扩大范围，不能直接说“你没说过”。
4. 当前上下文：每次仅装入相关资料。压缩这一层不改变源档案。更换模型或 embedding 后，可从源档案重建索引。

源档案采用 PostgreSQL 和对象存储；首先实现关键词、向量、时间、来源过滤的可重建检索。Graphiti 作为默认的概念／时间关系索引候选，在第 8 节小规模对照中验证；若有实际收益再加入，结果写入架构决策记录。Hindsight 仅为对照，不同时接入多套生产记忆框架。无论索引如何选，源档案与应用身份不得由该框架独占。

### 3.3 小 note 建议字段

`note_id`、课程／章节、概念、关联概念、用户原问题、有效解释、关键图、用户当时的理解／误解、未解决问题、相关未来用途、来源事件、创建与更正时间。

note 不把“看过解释”直接标为“掌握”。用户重新忘记时可展示此前最有用的解释，再按当前问题补充。

### 3.4 预备课与现场讨论

- 预备课优先当前可见内容及确实已取得的相邻课程内容；生成短解释、识别概念关系、预取旧 note。
- 实时讨论引用当前选区、相关课程材料、个人知识证据与近期对话。
- 多选深入方向应区分课程必需、补先修、选学兴趣；不增加用户必须完成的清单。
- 公式、图表与数值交互用可验证的渲染或计算；不能把随机生成的图当精确数学图。

### 3.5 多设备会话

建议每台设备作为同一会话下独立的媒体来源。服务端直接订阅多路屏幕与事件流，不要求真的显示三个桌面。每帧附 `device_id`、来源类型、采集时间、画面版本和课程／页面线索；保留各路清晰度，不只给模型一张低分辨率三屏拼图。

跨设备判断要区分：手机正在补充 iPad 课程的背景知识、手机内容无关、电脑正在运行相关工作 Agent。不能只按哪个设备最近活跃判为分心。设备掉线或画面过旧时标为未知；不能把最后一帧无限当作当前状态。

同一时刻指定一个主麦克风和一个播音设备，防止重复转写、回声和三个设备同时说话。用户应可切换主设备。已有会话和跨设备记忆归于同一个用户，课程和工作任务保留各自来源。

LiveKit 可作为传输候选，但默认 AgentSession 通常绑定单个参与者；需要实现明确的多路输入收集与协调，不能只让三台设备进房间就宣布完成。

### 3.6 自主备课与连接维护

后台任务队列独立于 iPad 前台生命周期运行。允许读取已授权课程、公开网页并制作可追溯的预习成果；不等于用户退出后仍自动重启设备录屏。

任务应记录：目标、来源版本、优先级、进度、输出、预算预留、停止条件与失败原因。内容未变化时复用成果；新课程资料发布后增量更新。实时讨论优先于后台预生成，达到预算阈值先暂停低优先级备课。

持续连接采用官方支持的登录／刷新流程。正常过期可自动续期，撤销权限或学校要求验证时停止相关同步，保留已取得资料，在合适时机请求重新连接。新增平台先说明所需资料及用途，完成该平台自己的授权。

本轮确认的自主范围是学习支持：读取、研究、生成笔记和计划、提醒用户。是否代做并提交作业、向老师或他人发消息、购买资源等是不同动作，不能从“auto mode”或“为了我好”推导为已获授权。

| 任务 | 初步处理方式 | 升级触发 |
| --- | --- | --- |
| 画面变化检测、计时、去重、缓存查询 | 确定性程序或合适的设备能力 | 数据不可用时报告状态，不靠大模型猜测 |
| 清晰字幕／基础翻译／材料检索整理 | 较便宜模型或专用服务，保留源文与定位 | 符号歧义、检索冲突、专业表达影响结论 |
| 批量课前短卡片／笔记草稿 | 适合任务的模型，按重要性抽检或复核 | 新核心概念、推导、与用户旧理解冲突 |
| 用户困惑、复杂推导、理解纠错、跨课规划 | 用户选定的旗舰模型与适当推理强度 | 根据问题复杂度进一步增加推理或拆分独立子任务 |
| 语音识别、语音合成、即时打断 | 实时音频专用链路 | 低可信转写先澄清，不能编造用户问题 |

任务难度不能只按“翻译”“查资料”等名称判定；数学翻译和关键来源判断也可能需要旗舰。便宜模型输出应附来源，重要任务不能把它的有损概括当作唯一输入。模型不确定、自检失败、用户说“没讲明白”等均触发升级。

优先做内容去重、增量解析、已生成解释复用、按需检索和有限预生成。多 Agent 仅用于可独立处理且确实有收益的工作，避免大量互相复述消耗 token。输入缓存和摘要不删除长期源档案。

预算包含输入／输出、音频、视觉、嵌入、图像生成与失败重试等 API 成本；调度前预留估计费用，调用后结算，汇率与价格按当时信息配置。并发任务不能各自认为还有全部预算。优先保留实时互动所需额度，达到限制时说明可用选项，不静默超支。

与全旗舰方案做同题对照：关键解释正确性、原材料对应、记忆召回、首个有效响应时间、用户追问次数和实际成本。未测试前不写节省百分比或等价保证。

### 3.8 订阅连接器与正式 API

把官方 Agent 连接器和原生模型 API 作为不同后端，分别记录能力、额度、认证状态、成本与支持的输入。官方 Agent 后端不应被假装成无差别的通用 API。首选连接器候选为 Codex App Server、未经修改的官方 Claude Code／获支持的 Agent SDK 路径、Gemini CLI；实现时复核版本和账号可用性。

Codex App Server 官方支持产品集成与由 Codex 管理的 ChatGPT 登录／刷新；Claude 当前帮助页说明 SDK 和非交互使用仍消耗订阅额度，并有官方登录与托管条件；Gemini CLI 支持 Google 账号认证。不得提取会话凭据、仿造私有请求或绕过官方配额来实现“订阅复用”。

个人自用的已登录 Agent 与将来向其他用户发行的服务要区分。直接 API 采用正式密钥与计费；供应商自身的聊天／编码客户端权益不意味着所有实时音频、视觉、生成图片等接口都由订阅覆盖。

### 3.9 提醒决策与退出

默认选型建议：会话内对话／语音为主，系统通知用于休息到点和确有必要的离线提醒，SMS 作为重要且临近截止事项的备用。微信、抖音作为后续可选适配，不成为核心功能依赖。

每个提醒关联真实任务、截止时间及来源、重要性依据、上次提醒、用户回应、下一次可提醒时间与失效时间。三设备与不同渠道共用去重状态。普通长期愿望仍留在下次学习会话中主动提起。

没有回复不能自动当作没有完成。反复未行动时先问原因、减少任务粒度或调整计划。结束陪学停止实时监督，后台备课与允许的低频提醒可继续；用户明确暂停提醒时停止。提醒间隔、日总量、安静时段及例外采用可调整配置，具体初始值应在可体验版本中校准，不记成用户已指定数字。

“退出”必须区分普通切换到 Safari／Canvas／主屏与真正结束陪学。前者是原页面学习的正常流程，不得因主 App 进入后台就结束会话。显式点结束陪学或停止系统广播时停止对应采集；强退主 App 后广播扩展是否停止必须真机验证，不能凭进程生命周期猜测。设计可见、可用的结束入口；服务端收到关闭事件即停止对应监督，心跳中断则标采集不可用并停止基于该源的判断，不自动重新开始采集，也不把最后一帧当实时。退出后台进程无法可靠发出关闭事件时，如实说明停止状态与系统操作。

督促可直说具体后果、指出承诺与行动的差距、提出最小下一步。不要以 AI 的情绪要求用户服从，不把一次回避归因为人格缺陷。重要判断需能解释依据，不能只写“模型觉得为了你好”。

## 5. 必须先验证的真实能力

1. 指定 iPad／系统上，用户留在 bCourses 真实播放页面或笔记 App 时，合法可用的圈选入口、解释呈现和返回流程。
2. 普通滚动／书写与提问选区区分；不截断原 App 的正常操作。
3. 课程声音与麦克风能否同时取得并区分；教师话语不会误触发“用户开口讨论”。具体网站、播放器及受保护内容逐项记录支持范围。
4. 字幕切换、视频继续播放、黑板推导变化时，选区与缓存解释是否仍对应正确帧和时间。
5. 后台语音陪伴、屏幕采集、计时与退出的行为；区分普通切回课程、显式结束、系统停止广播与强退主 App，停止采集后不假称仍看到用户屏幕。
6. 原页面模式不可行时，以真机结果说明哪些场景可用 Safari 扩展、并排助手或短暂切换。用户已接受不可行场景采用备选，按第 8 节执行并报告支持范围；支持原页面的场景仍优先保留原页面体验。

## 7. 关键产品流程与行为契约

### 7.1 首次设置与每天使用

首次设置：创建个人身份，选择／连接官方模型后端，连接 Google Calendar 和 bCourses，检测设备能力，启用所需系统共享与麦克风权限，安装／启用 Safari 扩展。其他平台和笔记目的地按需连接。步骤可断点继续，不因一个连接失败阻塞其余已可用功能。

日常：打开 App → 说今天目标或“继续昨天” → 从已保存项目、日程和进度恢复 → 完成系统要求的共享确认 → 回原课程。设备选择保留上次偏好并可随时调整，不要求每次重选，也不据此自动开启其他设备采集。除系统必须的动作，不重复收集链接、课程说明和登录。首页只显示当前项目、今天安排、可继续的位置与简洁进度，不展示冗长历史聊天。切回课程使主 App 进入后台属于正常使用，生命周期与结束陪学的区别见第 3.9 节。

### 7.2 输入模式

工具按钮常态只有直观图标，带辅助功能名称和选中状态；初次可出现一次性提示。Pencil Pro 捏合／双击仅作可选快捷方式，按钮始终可用。不要把是否配对作为唯一可用性判断，要检测真实输入能力。

| 模式 | Pencil 输入 | 有 Pencil 时手指输入 | 结束行为 |
| --- | --- | --- | --- |
| NAV 导航 | 交还当前页面／普通工具，不触发 AI | 正常点击、滚动、缩放和操作 | 默认状态 |
| ASK 提问 | 点词、短划选句、圈闭合区域 | 正常页面操作；可点击工具和解释卡 | 确定一个选区后恢复先前模式；卡片可保留 |
| WRITE 笔记 | 书写／绘图，擦除、撤销和重做 | 正常页面操作与工具操作，不画墨迹 | 持续到用户切换；每次结束笔划先本地保存 |

没有 Pencil 时，在显式进入的选区界面允许手指圈选；清楚显示选区状态，完成或取消立即恢复导航。该例外不能改变有 Pencil 时手指导航的规则。

这里的模式只作用于应用拥有或平台允许控制的界面。设置 PencilKit 的 `pencilOnly` 不自动保证手指可以穿过覆盖层点击原网页；必须真实测试页面按钮、滚动、缩放及视频进度条。无法同时满足时使用第 8 节备选，不用系统级伪触摸补出未经允许的权限。

选区带固定 `frame_id / source_version / media_position / bbox或polygon`。用户继续滚动或视频继续播放不会改变已选内容。圈不闭合或附近有两个可能对象时，显示可调整选框；不能假装知道用户指的是哪一个。

### 7.3 点读与主动教学

点读先呈现当前语境下够用的解释，原始来源可展开。根据已有知识与课程用途选文字、公式、图示；底部给可多选的深入方向。默认最多显示 4 个方向，更多收起。点击和主动教学卡片均不自动朗读。

主动教学可由相关概念再次出现、明确错误回答、反复回看、先修缺口或用户目标触发。行为是先提供小卡片：换个图解释、回顾旧 note、做一道可跳过的题。反复回看只是线索；跳过不等于不会。初始默认同一概念一次主动提示后，未回应时至少 15 分钟不重复，正常一次会话不积压多张提示；这些是可调参数。

开口向 AI 提问才切入语音讨论；麦克风中课程老师的声音、其他设备播音不能当作用户提问。声音无法分离时提供显式按住说话入口，不假称自动分辨已可靠。默认语速 1.3 倍且可调；用户打断立即停止旧播音及未播放队列，长推理继续与否依据新话语决定。

监督走神、休息到点的语音提醒使用独立调度规则，不混入“主动教学可以随时大声讲课”。视频仍由用户自己暂停。

### 7.4 自己写的笔记与 AI 笔记

分为三层：

1. **用户原稿**：可编辑 Pencil 笔划、原始布局及版本。先本地保存，再后台同步；识别结果是索引，不能替换墨迹。
2. **当时上下文**：原画面／局部裁剪、来源链接、课程或自学项目、可靠的视频位置／页码和相关讨论。开始写时捕获锚点，页面发生实质改变后继续写则新增上下文段，不强制暂停播放器。
3. **AI 补充**：必要的图、公式、少量关联说明，单独可隐藏／删除；不在用户原字迹上改写。公式和截图来自真实材料；补画属于 AI 说明，不能伪装成老师画过的图。

AI 自动学习 note 另存：默认一个标题、最多 3 个简短要点、1 个必要公式或图；展开才显示推导与更多例子。此为防啰嗦的初始默认，不是硬性字数截断。完整对话仍保存在后台。用户删减某类补充后记录风格偏好，不能下次又自动加回。

### 7.5 外部笔记存放

| 目的地 | 本规格确定的交付 | 成功判定与限制 |
| --- | --- | --- |
| 本 App | 自动保存可编辑墨迹、图文层、上下文与检索索引；AI note 默认在此 | 本地提交与服务器同步分别显示状态，离线仍可写 |
| Notability，用户偏好 | 生成排版好的 PDF／图片，通过官方支持的分享／导入路径送出 | 未核实静默创建／追加的公共接口；不能把调起分享面板当成已导入，也不能把云端备份当双向同步 |
| OneNote，自动外部归档选项 | 连接一次个人 Microsoft 账号后，通过 Microsoft Graph 创建图文页面 | 接口成功返回页面 ID／链接才算成功；手写渲染为图片，原始可编辑墨迹留在本 App，可附原稿／链接 |
| Google Keep 等其他软件 | 统一导出适配器扩展点 | Keep 当前官方 API 的企业授权条件不适合作普通个人账号默认依赖；未验证的自动写入不计作已实现 |

导出保留用户原稿为主体，添加必要课程截图和简短出处。PDF／PNG 不宣称保持 Notability 或 OneNote 的原生可编辑笔划。笔记版本与外部目标 ID 对应；写入响应丢失进入 `unknown` 并查询对账，不能盲目重试制造多份。Notability 分享由系统决定需要的交互，功能完成状态如实显示“文件已准备／已分享，需在目标 App 完成导入”。

### 7.6 通用学习项目与 Google Calendar

正式课、自学计划、工作学习都采用 `LearningProject`，允许零个 Canvas ID、多种来源和多门课程的概念联系。添加任意 URL 时立即保存记录；解析和备课后台完成。区分稳定页面地址、临时签名下载地址和授权凭据。保留有语义的查询参数及旧快照，不通过粗暴删 query 把不同视频误当同一来源。

Google Calendar 首批实现：选定的多个日历、初始同步、增量变化、重复事件实例、取消与改期、时区和后台续期。用户已有“机器人 AI 计划”可关联已保存项目；若事件只写“学习 AI”且有多个候选，标记歧义，下次会话短问一次并记住结果，不凭标题编造计划。

阅读日历不意味着自动改动已有安排。本应用生成学习安排时，可在已授权的专用学习日历中写入并使用内部项目 ID 关联；修改其他来源的既有事件需有对应明确指令或预先配置规则。先查重，禁止为已有计划再建一套重复安排。

同步契约：每个账号／日历独立游标；分页完成后提交 `nextSyncToken`；处理删除／取消；同步 token 失效只重建该日历投影，不删除项目、目标、笔记或记忆。Google 推送作为变化信号，仍需增量拉取和周期对账。初始默认会话开始即刷新、空闲时每 15 分钟检查一次，有推送后合并触发；无变更不反复备课。

保存事件的 IANA 时区，默认显示 America/Los_Angeles，不固定 UTC−7。全天事件保存日期而不是伪造午夜截止时刻。重复实例保留 master 和原始实例时间。后台 OAuth 采用离线授权及安全刷新，测试环境的 token 期限不可当作产品最终免重登能力。

## 8. 能力验证关卡：先证实，再承诺

Codex 首个可运行成果应是小型能力验证应用及结果表，不是完整漂亮但全是 mock 的学习界面。每项记录设备／OS／SDK 版本、真实操作、通过／失败、证据和启用的备选。

| 关卡 | 必须验证 | 不通过时的确定路线 |
| --- | --- | --- |
| G1 原页面输入 | Safari 中图标、Pencil 圈选／笔记、手指正常导航；含真实课程视频 iframe、全屏与字幕 | 对受支持页面启用原位模式；其他页面采用课程旁的助手区域，其次快捷进入当前冻结画面；无需用户手动截图保存上传 |
| G2 原生跨 App | Canvas／Notability 上能否通过公开接口展示圈写界面与接收输入 | 保留跨 App 看屏幕＋语音；圈写在本 App／并排助手的已捕获画面完成，明确不是全局悬浮能力 |
| G3 音画与三设备 | 课程音轨、麦克风、板书分辨率、三屏时间对齐、启停权限、旧帧失效 | 音轨不可得时用已授权字幕；无字幕标缺失。不能把不可访问声音编成历史。禁用不可用媒体源，不阻塞其他源 |
| G4 账号连接 | Calendar／Canvas 真实授权刷新；订阅 Agent 的官方认证、额度和请求输入 | 支持已可用连接；失效请求重连；缺少权限明确标 `needs_auth/unsupported`；正式 API 作为已授权后备 |
| G5 外部笔记 | Notability 实际导入操作；OneNote 真实页面创建／读取回执 | Notability 保持分享导入；OneNote 未连接时本地保存＋待同步，不丢原稿 |
| G6 长期检索 | 本地混合检索与 Graphiti 候选在 30 组模糊回忆／历史更正样例上的质量与成本 | 保留源档案；选择实测较可靠方案并写 ADR。不得为接框架而跳过召回验收 |

用户已接受原页面确实不可行时以可用性优先。备选流程须尽量一步进入、一步返回并保持课程位置，不重新要求用户搬全部材料。不可用能力可分范围交付，但必须直说哪些界面经过真机验证。

## 9. 实现结构与核心数据契约

### 9.1 默认技术结构

| 模块 | 默认方案与职责 |
| --- | --- |
| iPad／iPhone | 原生 SwiftUI＋UIKit；PencilKit 保存笔迹；AVFoundation 音频；按实际 OS 使用已验证屏幕共享 API；SwiftData/SQLite 保存离线事件和笔记 |
| Safari 扩展 | TypeScript 内容脚本＋原生消息桥；仅获授权页面注入控件／获取可用结构；图形区域仍可基于画面识别 |
| Windows 同伴客户端 | Electron＋TypeScript，选择屏幕／窗口共享、主麦克风、会话与已有工作 Agent 连接；不要求承担主阅读体验 |
| 服务端 | Python＋FastAPI，应用 HTTP／WebSocket 契约，独立 worker；固定工作流优先，不为每一步创建 Agent |
| 实时传输 | LiveKit Swift／JS 客户端与媒体轨道；自定义多设备收集，不能只用默认单参与者会话 |
| 持久化 | PostgreSQL：身份、源事件、日程投影、状态、版本、预算账本；S3 兼容对象存储：关键图、笔迹、导出文件；Redis 仅队列／临时缓存，不作为唯一记忆 |
| 检索与模型 | 可重建全文／向量索引＋经 G6 选定的关系索引；模型与 Agent 后端统一能力适配器；官方 API／SDK，版本锁定 |
| 公式和图 | Markdown＋KaTeX／MathJax、SVG、确定性绘图；互动演示在受限渲染环境中运行；真实课程裁图优先 |

部署先采用单用户后端和 Docker Compose 开发配置，不上 Kubernetes。Windows 可以运行同伴客户端和后端；iOS 编译／签名与真机安装由 macOS＋Xcode 开发环境或 macOS 构建服务完成。没有该环境时如实标记 iOS 未编译／未真机测，不能用网页截图冒充。

依赖采用实施时可用稳定版本并固定 lockfile；新增服务需说明解决哪个已验证问题。安装或启用来源连接时不得把网页、课程文档内的指令当作应用权限。

### 9.2 实体最小字段

所有可归属用户的数据都有 `user_id`。时间戳存 UTC 并保留来源时区；视频偏移单独存秒。以下为领域字段，数据库索引与迁移由实现补齐，不得省略来源关系。

| 实体 | 必需字段／约束 |
| --- | --- |
| LearningProject | id、kind(course/self_study/work_learning)、title、aliases、goal_ids、source_ids、unit_ids、status、curriculum_version；不得要求 Canvas ID |
| LearningUnit | id、project_id、title、sequence、prerequisites、source_locators、progress_state、progress_evidence_ids；内容进度与掌握分开 |
| Source／Snapshot | id、project_id、type、original_url、canonical_url、connection_id、access_status、version、content_hash、fetched_at、locator_schema；旧版本可追溯 |
| Connection | id、provider、account_subject、scopes、status、last_success、needs_reconnect；令牌仅在加密凭据存储，不进模型上下文 |
| CalendarEvent／CalendarLink | account_id＋calendar_id＋event_id 唯一；recurring_event_id、original_start、start/end、timezone、status、source_revision；link 含 project/unit/goal、关联依据与置信度 |
| Session／DeviceStream | session_id、active_project_ids、goal_ids、status；device_id、platform、capabilities、enabled_tracks、last_frame_at、primary_audio_role |
| Observation | event_id、device_id、session_id、source/version、captured_at、received_at、actor(user/teacher/assistant/unknown)、text、frame_id、media_position、confidence、gap_flags |
| Selection | id、frame_id、source/version、bbox/polygon、selected_text、concept_candidates、input_mode、created_at；始终绑定固定画面 |
| ConversationTurn | id、session_id、actor、text、selection_id、source_event_ids、timestamps、model_backend；完整交互保存，正常 UI 不铺长聊天 |
| Concept／MasteryEvidence | concept_id、aliases、project_links、prerequisite/related 边；evidence_id、type、自述／回答／迁移结果、source_turn、time、confidence |
| Note／Revision | note_id、kind(ai/handwritten)、project/concepts、title、blocks、ink_blob_id、context_segments、source_event_ids、revision、base_revision、authorship；AI 层与用户原稿分开 |
| ExportJob | note_id、revision、target、external_id、status、artifact_id、attempt_count、last_error；发送状态不等于外部已保存 |
| Goal／Reminder | goal_id、user_intent、priority_evidence、deadline/source、state、next_session_prompt；reminder 有 due_at、expires_at、channel、dedupe_key、ack、next_allowed_at |
| BackgroundJob | id、kind、source_versions、idempotency_key、state、checkpoint、budget_reservation、attempts、cancel_requested、outputs |
| UsageLedger | reservation_id、job/request、backend、price_version、currency、estimated_max、actual、state；订阅配额与 API 金钱分开 |

掌握状态初值：`unknown → encountered → practicing → demonstrated`，必要时变为 `needs_review`；迁移能力另附证据。状态只是一种摘要，所有依据保留。用户可纠正 AI 的判断，不因纠正就删除过去学习记录。

### 9.3 来源解析状态

`registered → fetched → parsed → indexed → ready`；并行异常为 `needs_auth / temporarily_unavailable / unsupported / failed`。保存 URL 不等于已读正文；下载成功不等于字幕／公式已正确解析；索引完成不等于每个答案都有证据。前台只用简短状态提示，不暴露内部术语堆砌。

## 10. 应用接口与后台状态机

以下路径是本产品内部接口设计，不是外部供应商已有 API。使用版本化 `/v1`，生成 OpenAPI 和客户端类型。所有写操作验证用户身份；支持的幂等操作使用 `Idempotency-Key`；版本写入用 `base_revision`，冲突返回 409 而非覆盖。

| 接口 | 输入与结果 |
| --- | --- |
| `POST /v1/sources` | URL 或已连接来源标识、可选 project；返回持久 source_id、是否已有、解析状态，并排队增量处理 |
| `POST /v1/connections/{provider}/start` | 需要的 scopes、客户端回调信息；返回官方授权入口；callback 校验 state 并保存凭据 |
| `POST /v1/connections/{id}/sync` | 可选同步范围；返回 job_id，读取状态不用重复启动 |
| `GET /v1/projects`、`GET /v1/projects/{id}/progress` | 统一返回课程、自学与工作项目；进度包含依据与更新时间 |
| `GET /v1/agenda` | 显示时区和时间范围；合并已选日历、学习项目关联、实际进度，未知关联明确保留 |
| `POST /v1/sessions` | 今日目标／continue、project_ids；返回 session_id、恢复位置、需要的权限与已可用能力 |
| `POST /v1/sessions/{id}/devices` | 设备能力、配对凭证、启用轨道；返回受限短期媒体权限；主麦克风角色唯一 |
| `POST /v1/events:batch` | 稳定 event_id、每设备序号、时间与来源；去重落盘，返回已接受序号；断线客户端只重传未确认部分 |
| `POST /v1/explanations` | selection_id、project、知识画像版本、mode=silent；返回 request_id、cache_hit、可用短卡或生成状态 |
| `WS /v1/sessions/{id}/events` | 有序事件：card_ready、answer_delta、note_updated、voice_state、job_state、capability_changed；可按 last_event_id 重连 |
| `POST /v1/voice/{turn_id}/interrupt` | 先客户端停播，再服务端取消当前生成／旧音频；返回真实 cancelled/finishing 状态 |
| `PUT /v1/notes/{id}` | base_revision、笔划／区块增量、context segments；返回新版本和持久化状态 |
| `POST /v1/notes/{id}/exports` | revision、target、format；返回 ExportJob，不在排队时声称已外部保存 |
| `POST /v1/memory/search` | 模糊问题、可选课程／时间线索；返回 note、原话、画面与来源事件，附未找到／歧义状态 |
| `POST /v1/goals`、`PATCH /v1/goals/{id}` | 保存随口目标、更正和完成依据；模糊愿望默认 next_session，不自动产生大量通知 |
| `POST /v1/sessions/{id}/end` | 停止本次所有实时轨道和监督；结果列仍在运行的已授权备课任务 |
| `POST /v1/reminders/pause` | 范围与可选结束时间；持久化并取消匹配的待发项，跨设备同步 |
| `POST /v1/jobs/{id}/cancel` | 写入取消请求，worker 在安全点停止；未知外部执行结果不假报取消成功 |
| `GET /v1/usage` | 本月 API 实际费用／预留、订阅可用状态、预测；不展示虚假的余额 |
| `POST /v1/work-agents/{id}/commands` | 已授权 task_id 和 start/steer/pause/cancel；回传实际 agent 执行事件，区分口头建议与已执行动作 |

媒体走实时传输和受权限控制的对象上传，不把每帧大图塞进普通聊天日志。配对 token 有限期；长效凭据不交给第三方课程页面。

后台任务状态：`queued → running → completed`，可进入 `waiting_for_auth / retry_scheduled / failed / cancelling / cancelled`。初始默认暂时性故障最多重试 3 次，指数退避；写入型外部动作遇到超时先查询是否生效。自发网页研究按明确问题拆任务，每任务有时间、调用数和费用上限；未完成可检查点续作，不能无限循环。

说明不同停止动作：结束陪学停止实时采集与监督；暂停提醒停止匹配提醒；暂停自主备课停止对应 worker；撤销来源停止读取／续期；删除记忆删除对应源与派生副本，不能被后台旧任务重新写回。

## 11. 验收标准与测量方法

所有数字是首轮工程目标，不是当前实测成绩。测试报告需注明设备、OS、网络、后端模型、样本数和失败样例。不能用“正在思考”或空泛开场词算有效解释。

| 指标 | 初始目标 |
| --- | --- |
| 已预取本地解释 | 点选确认至有效卡片渲染 P95 ≤300 ms |
| 未命中反馈 | 150 ms 内显示明确生成状态；普通短解释首个有效内容目标 P50 ≤3 s、P95 ≤6 s，复杂推导另报分布，不隐瞒长尾 |
| 语音打断 | 收到用户打断信号到客户端停播 P95 ≤300 ms；取消旧队列，不串入下一回合 |
| 本地手写 | 笔划结束后 500 ms 内持久化；无网络时退出并重开不丢已确认笔划 |
| 输入误触 | 固定 100 组滚动、点击、缩放、拖视频与书写脚本中，不能触发非预期 AI 查询；真机手工检查记入报告 |
| 精确历史检索 | 至少 50 个历史事实／更正／跨课相似内容样例，Top-5 证据召回目标 ≥95%；不能把错误来源当成功 |
| 模糊画面回忆 | 至少 30 个时间不精确／描述近似样例，返回结果可追溯到正确画面与原话；失败例保留，不用模型编造补齐 |
| 记忆保存 | 注入足以触发多次上下文压缩的后续资料，换模型、重启、重建索引后，早期源记录内容校验不变 |
| 模型分流 | 至少 30 个真实课程问题同条件对比全旗舰，记录重大错误、遗漏、有效响应时间、用户选择与成本；发现教学错误类别则禁用该类降级 |
| 预算与并发 | 并发预留不能超过剩余额度；缺少价格或额度未知不能宣称免费；达到上限停止新增计费任务，保留已有内容和可用订阅能力 |
| 外部写入 | 本地、同步、导出、外部确认分开；网络中断后重试不制造重复 note／日程／消息 |

必要测试分层：领域状态和幂等用单元／集成测试；供应商连接用真实最小调用；触控、录屏、音频、后台和返回位置必须真机测试。mock 仅用于开发，不计作外部接通或平台能力通过。
