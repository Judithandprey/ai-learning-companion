## 1. 做题流程与状态

进入当前题目并确定题面版本 → 选择或混用网页选项、文字／公式、网页手写、外部笔记或本产品原屏幕笔 → 默认自主探索 → 按请求检查局部或逐级提示 → 用户决定继续尝试或看解法 → 按请求复盘 → 可跳过的针对性练习 → 保存过程与证据。

“自主探索／提示／复盘”是教学状态；原有 `NAV / ASK / WRITE` 是输入模式，两者独立。正常书写可以记录已授权的过程，但不能因此自动请求解释或弹出解法。原 R08 和正常手指操作保障继续适用。

建议只增加少量清楚入口：“让我先试”“检查这一步”“给点提示”“看解法”“复盘”。语音表达同样有效。不要把每种后台状态都做成必须操作的按钮。

屏幕最终解答完成后及时出现是否整理及可用去向的简洁选择，不要求用户另问。实际完成与正确答案不同；停顿、离屏或正确结果不自动证明完成。无法确定时用一次短问合并确认完成和整理意愿，拒绝后不对同题反复追问；继续改写／切题使旧提示失效。依据已连接作业来源关联课程、作业、题号和版本，有歧义才短问。Notability 常用但不写死，bCourses 是已授权来源而非自动提交目的地；只呈现实际可用的归档／对应 PDF 文档／预览／暂不整理路径。完整规则见[已确认决定](intent-and-decisions.md#3-本轮已确认决定)。

### 原屏幕标注与备选的判定

R59 要求原页面仍可见可操作，用本产品的笔直接在当前共享实时画面上写，AI 真正
收到叠加后的画面及可用笔迹；NAV/ASK/WRITE 与教学状态分离。滚动／缩放使用可验证
的题面与坐标锚点，切题或无法可靠重定位时冻结原锚点并提示，不能无声移到另一题。
停止共享后不发送新实时帧／笔迹或让旧画面假装仍实时；历史保存状态另行说明。

原屏幕笔保留内容挂靠与屏幕固定两种显示模式，分别验证滚缩、重排、换页、视频变化及来源恢复。两者始终保留书写时原稿与上下文；固定显示不丢出处，内容挂靠也不承诺任意视频物体追踪。模式只决定显示，不强制用途或外送去向；混合书写与改用途不能漂到另一题。平台限制和 A45 备选仍另列，不能只做固定草稿就算双模式或 A44 通过。

受限路径可以提供自动捕获画面、独立画布或并排草稿，不要求每步手动截图搬运。
使用时明示备选与冻结状态，原页变化要提示并保留一步返回。A44/R59 原位结果与
A45 备选结果分开记录；可以继续其他可行工作，不能以备选通过给原位要求盖章。

### 原屏幕课堂笔记到 Notability

联动主规格 §7.4/7.5、R46–R48、R59 和 A26–A28/A46。原笔迹与当时来源、画面、
可靠视频位置独立保存；AI 的图、公式、简短说明为单独层，不能替换或改写原稿。
按官方支持分享／导入路径归档 Notability。记录文件准备、分享、待导入、实际导入
及失败／未知状态；调起分享面板不能算已导入，不能承诺无公共接口的静默自动写入。
PDF/PNG 不等于 Notability 原生可编辑笔划，本 App 保存的原始笔迹仍独立可编辑。
A46 必须分别核对原屏幕书写、保存／来源／AI层及实际目标导入；任一失败或备选
如实报告，成功导出不能补齐未实现的原屏幕笔。

AI 依据实际情境区分学习笔记和作业草稿，不强迫逐笔手动分类；拿不准才最小澄清，用户可更正。笔记按规则送 Notability，草稿不自动外送但保存完整试错；其中形成最终解答时照上文询问整理。整理须保留用户实际答案、推导、原始布局与来源，AI 建议／修改分开可预览，不暗中纠错或换成标准答案。错误用途标签不删除原稿，分享／待导入／已导入不能混记。

## 2. 过程证据与数据建议

[音频与屏幕补充规范](audio-screen-interpretation.md) R60/A47–A49 同时覆盖口头尝试：保留犹豫、自我修正、否定、放弃的分支及原始 ASR 候选，语境修订和用户确认独立记录，不能把真实推理错误“修成”正确答案。AUDIO-02–10/AUDIO-13–15 要求实际授权声音与当时屏幕证据、可纠正人物归属、实时课堂／视频音轨及独立停止；缺音频不能从转写编造语气。无需录音上传，不扩永久录音，探索／全渠道披露约束仍有效；AVTEST-01–12 全部 not_run。

复用现有 Session、Observation、Frame、NoteRevision 和独立源档案，在后续经总工统一版本化的共享契约中表达下列领域概念；不建立第二套用户身份或孤立的错题数据库。

| 概念 | 最小需要表达的关系 |
| --- | --- |
| ProblemAttempt | 当前题面及版本、作答入口及切换关系、尝试 ID、上次尝试、开始／结束状态、关联课程与来源；同题重做与新题区分 |
| AttemptStep / Revision | 步骤／操作 ID、父步骤或分支、替代／撤销关系、前后版本、原始事件与画面、设备序号和时间、用户输入／网站反馈／AI 帮助的出处；不能仅靠墙钟排序跨设备事件 |
| ObservationCoverage | 获准网页状态／自有笔迹操作／外部视觉／混合、实时或冻结状态、有效覆盖区间、未确认区间、画面新鲜度及符号歧义；没有报告丢帧也不等于证明过程完整 |

| LearningPreference | 默认学习语言、technical terms 策略、中文提示偏好、探索／提示偏好、当前问题临时覆盖 |

原屏幕笔记继续复用 NoteRevision 的可编辑原稿、当时上下文和独立 AI 层；坐标变换、题面切换及叠加画面实际送达依据必须可追溯。外部归档复用 ExportJob 的真实状态，不另建孤立存储。所有这些是后续 P0-08 的设计输入，不提前改 v0.1.0。

显示模式、用途判定与更正、解答完成依据和不确定状态、整理同意／拒绝及真实目的地分开建模；保留书写时来源和当前显示关系，不把用户选择解释成固定数据库字段。整理版本与原稿独立关联；已见 AI 帮助不能因草稿升级最终解答或导出删层而变成独立掌握。

擦除和撤销是用户原稿的操作，不是 AI 将旧步骤悄悄替换；视觉变化也不能直接当作用户的完整理由。对“不知道你为什么这样改”保留未知值。

平台依据：Apple 的应用隔离规则要求通过系统明确提供的服务访问其他 App 数据，而自有 PencilKit 画布另有绘图变更与工具操作回调。因此，采用以下工程边界：应自行保存自有画布的编辑历史，不能从“已共享 Notability 屏幕”推导为“已取得它完整的撤销栈”。[Apple 运行时安全](https://support.apple.com/guide/security/security-of-runtime-process-sec15bfe098e/web)、[PKCanvasViewDelegate](https://developer.apple.com/documentation/pencilkit/pkcanvasviewdelegate)。Apple 也记录了帧处理不及时导致采集停顿和丢帧的情况，这支持对短暂试错单独验证，而不以开启录屏作为完整记录的证明。[ScreenCaptureKit 帧处理说明](https://developer.apple.com/videos/play/wwdc2022/10155/)。这些是文档依据，不是本项目真机通过结果。

### 采集完整性分级与报告

以下分级名称是工程默认，实际能力须按 App、设备、OS、来源及覆盖区间报告：

| 路径 | 可作出的证据声明 | 必须保留的限制 |
| --- | --- | --- |
| 结构化操作 | 逐站实测可读的授权网页选择／输入状态，或本产品实际记录的可编辑笔迹、写入／擦除／撤销／重做、版本与分支关系 | 未收到事件、序号缺口、未确认同步区间明确未知；有事件通道不等于已证明无漏步 |
| 外部视觉观察 | 授权屏幕流中实际观察到的画面、变化及时间范围 | 不能取得未暴露的语义操作或完整撤销栈；短暂改写、遮挡、模糊和丢帧可能不可恢复 |
| 混合证据 | 同一过程中的结构化事件与视觉帧互相定位 | 分别标注出处与对齐可信度；冲突或不一致留待确认，不能拼成假步骤 |
| 缺失／不确定区间 | 失联、画面过旧、缺帧、符号歧义或理由未知 | 用最终答案反推中间步骤不能填补缺口；没有报告丢帧不是完整性的证明 |

本产品笔与授权网页操作的目标是保存实际可取得的历史；外部 App 像素的承诺上限是实测可观察过程。原屏幕叠层能力须按入口矩阵单独验证，不能由共享像素推定。
界面用简短共享状态与失联提示说明是否仍可见，不把内部字段堆给用户。
人工参考过程与采集输出逐项比较后才能报告保留率及顺序／分支准确率。
原因、动机或修改理由没有被用户表达时保持未知；必要时最小澄清，允许暂不回答。

## 3. 全渠道防提前泄题

仅修改模型提示词不够。请求、缓存与展示都要携带尝试版本、教学状态、允许提示程度、偏好版本；检查当前用户意图后才能显示结果。

- 请求“给点提示”时，不能复用以前生成的完整解法卡。概念提示也可能间接泄题，验收要检查实际内容。
- 用户已经改正、切题或说“先别告诉我”时，旧卡片和等待播放的语音要取消或失效。缓存可以保留，但不得错误呈现。
- 卡片标题、通知预览、AI 补图、复盘摘要和语音使用一致的披露规则，不能从旁路泄露答案。
- 用户在另一设备更改帮助程度时，要同步到同一题目会话；暂时失联则不能基于过时许可主动播出答案。

## 6. 验收与测量

验收定义使用主规格 §6 的 A30–A46，不另建一套相互偏离的验收编号。

同时运行[决定记录中的五项 INTENT 用例](intent-and-decisions.md#4-直接验收与追踪)：两模式、混合用途与纠正、完成时提示、运行时目的地选择、忠实整理／真实导入。它们是原 R 与 A 的命名子案例，当前均未运行／未验收；G7 按路径单列结果，不能把一次标签检查当语义或设备通过。原 R01–R50 的其他行为仍按[原目标验证](original-goal-verification.md)逐条验收。

**G7 做题过程、原屏幕笔记与克制提示**：能力矩阵按上述作答入口分别评估网页行为、自有结构化操作、外部视觉及原屏幕标注；本产品实时叠层按网页、Windows、iPad/iPhone 原生 App 分列，不要求所有外部 App 都通过；受限路径如实标注，P1 可在一条明确支持的路径完成单题闭环，但画布／冻结备选不构成 R59/A44 通过，Notability 完整链路按 A46 独立取证。P0 可先用合成样例测试协议、排序、缓存失效和教学策略；真实外部 App 与 Pencil 的验收必须单独在设备上执行。

首轮工程默认至少准备 30 组有标注的过程样例，包含快改、回退、分支、合理替代解法、错误理由碰巧正确、缺帧和未知动机。分别报告关键步骤保留率、顺序／分支准确率、误判正确解法、无依据诊断和提示越界。固定验收集中提前泄题、伪造步骤和错误标记独立掌握应为零；有限样本通过不等于模型在所有题目上都有保证。规则用程序验证，数学正确性与语义泄题用独立复核及真实用户试用验证，不能只让同一个模型自评。

实时性能沿用 §11 的测量原则，同时增加画面新鲜度和关键改写被保存的延迟；报告采集、同步、识别、推理、显示各段延迟和失败样例。进度动画不能算有效帮助。具体设备目标在 G7 首轮测量后确定，不将未测数字写成已达成。

没有 Mac／Xcode 和可操作设备路径时，平台结果仍须标为未编译或未真机验证；
网页测试、源代码阅读或平台文档均不能替代 A41/A44/A46 的相应设备及目标导入验证。A42–A46 加入原 A30–A41 和 A26–A28 证据范围；正确选项且理由未知不判独立掌握，备选与原位不能混计。

## 7. 阶段衔接与职责

这组能力已进入核心产品范围。保留正在运行的 P0 任务，在安全边界衔接过程证据和帮助策略。以下是工程阶段默认，可依据验证调整，不是用户指定的固定排期；不得因此省略原 P1 看课、点读、记忆闭环。

1. **P0 增量：** 总工统一契约、G7 和追踪表；学习角色制作过程样例与提示越界评测；平台角色验证当前设备能取得什么过程证据。沿用并扩充现有 P0-08–P0-13 任务卡，不重复创建同类任务，不把已有验收描述改成已通过。
2. **P1 做出最小闭环：** 在至少一条明确支持的 iPad 路径中，实现一道真实题的开始、自主尝试、请求提示、复盘、保存和次日回查。若跨 App 过程不足，保留原页面看屏，可提供明确的作答画布／冻结／并排备选；它们不使原屏幕 R59/A44 通过。按实际支持范围继续原位验证，不把用户所有学习迁移成上传 PDF 聊天。
3. **P2 提高教学效果：** 加入针对性微练习、跨题复习、帮助程度与独立掌握评价；完善外部笔记和复杂分支诊断，联动 A46/A26–A28 取证原屏幕课堂笔记到 Notability 的实际导入链路，不能用备选掩盖原位缺口。
