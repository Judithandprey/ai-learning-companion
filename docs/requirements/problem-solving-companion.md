## 1. 做题流程与状态

进入当前题目 → 默认自主探索 → 按请求检查局部或逐级提示 → 用户决定继续尝试或看解法 → 按请求复盘 → 可跳过的针对性练习 → 保存过程与证据。

“自主探索／提示／复盘”是教学状态；原有 `NAV / ASK / WRITE` 是输入模式，两者独立。正常书写可以记录已授权的过程，但不能因此自动请求解释或弹出解法。原 R08 和正常手指操作保障继续适用。

建议只增加少量清楚入口：“让我先试”“检查这一步”“给点提示”“看解法”“复盘”。语音表达同样有效。不要把每种后台状态都做成必须操作的按钮。

## 2. 过程证据与数据建议

复用现有 Session、Observation、Frame、NoteRevision 和独立源档案，在后续经总工统一版本化的共享契约中表达下列领域概念；不建立第二套用户身份或孤立的错题数据库。

| 概念 | 最小需要表达的关系 |
| --- | --- |
| ProblemAttempt | 当前题面及版本、尝试 ID、上次尝试、开始／结束状态、关联课程与来源；同题重做与新题区分 |
| AttemptStep / Revision | 步骤／操作 ID、父步骤或分支、替代／撤销关系、前后版本、原始事件与画面、设备序号和时间；不能仅靠墙钟排序跨设备事件 |
| ObservationCoverage | 结构化事件或视觉观察、有效覆盖区间、未确认区间、画面新鲜度及符号歧义；没有报告丢帧也不等于证明过程完整 |
| AssistanceEvent | 用户请求、当时尝试版本、允许披露程度、实际提示及是否已显示／播放；后续掌握证据引用它 |
| DiagnosisRevision | 针对哪次尝试、偏差所在步骤或候选区间、证据、待确认理由、有效修正、用户更正与诊断版本 |
| LearningPreference | 默认学习语言、technical terms 策略、中文提示偏好、探索／提示偏好、当前问题临时覆盖 |

擦除和撤销是用户原稿的操作，不是 AI 将旧步骤悄悄替换；视觉变化也不能直接当作用户的完整理由。对“不知道你为什么这样改”保留未知值。

平台依据：Apple 的应用隔离规则要求通过系统明确提供的服务访问其他 App 数据，而自有 PencilKit 画布另有绘图变更与工具操作回调。因此，采用以下工程边界：应自行保存自有画布的编辑历史，不能从“已共享 Notability 屏幕”推导为“已取得它完整的撤销栈”。[Apple 运行时安全](https://support.apple.com/guide/security/security-of-runtime-process-sec15bfe098e/web)、[PKCanvasViewDelegate](https://developer.apple.com/documentation/pencilkit/pkcanvasviewdelegate)。Apple 也记录了帧处理不及时导致采集停顿和丢帧的情况，这支持对短暂试错单独验证，而不以开启录屏作为完整记录的证明。[ScreenCaptureKit 帧处理说明](https://developer.apple.com/videos/play/wwdc2022/10155/)。这些是文档依据，不是本项目真机通过结果。

### 采集完整性分级与报告

以下分级名称是工程默认，实际能力须按 App、设备、OS、来源及覆盖区间报告：

| 路径 | 可作出的证据声明 | 必须保留的限制 |
| --- | --- | --- |
| 结构化操作 | 本 App 实际记录的可编辑笔迹、写入／擦除／撤销／重做、版本与分支关系 | 未收到事件、序号缺口、未确认同步区间明确未知；有事件通道不等于已证明无漏步 |
| 外部视觉观察 | 授权屏幕流中实际观察到的画面、变化及时间范围 | 不能取得未暴露的语义操作或完整撤销栈；短暂改写、遮挡、模糊和丢帧可能不可恢复 |
| 混合证据 | 同一过程中的结构化事件与视觉帧互相定位 | 分别标注出处与对齐可信度；冲突或不一致留待确认，不能拼成假步骤 |
| 缺失／不确定区间 | 失联、画面过旧、缺帧、符号歧义或理由未知 | 用最终答案反推中间步骤不能填补缺口；没有报告丢帧不是完整性的证明 |

本 App 的目标是保存实际可取得的操作历史；外部 App 的承诺上限是实测可观察过程。
界面用简短共享状态与失联提示说明是否仍可见，不把内部字段堆给用户。
人工参考过程与采集输出逐项比较后才能报告保留率及顺序／分支准确率。
原因、动机或修改理由没有被用户表达时保持未知；必要时最小澄清，允许暂不回答。

## 3. 全渠道防提前泄题

仅修改模型提示词不够。请求、缓存与展示都要携带尝试版本、教学状态、允许提示程度、偏好版本；检查当前用户意图后才能显示结果。

- 请求“给点提示”时，不能复用以前生成的完整解法卡。概念提示也可能间接泄题，验收要检查实际内容。
- 用户已经改正、切题或说“先别告诉我”时，旧卡片和等待播放的语音要取消或失效。缓存可以保留，但不得错误呈现。
- 卡片标题、通知预览、AI 补图、复盘摘要和语音使用一致的披露规则，不能从旁路泄露答案。
- 用户在另一设备更改帮助程度时，要同步到同一题目会话；暂时失联则不能基于过时许可主动播出答案。

## 5. 学习语言与原记录

R57 的默认偏好适用于课程解释、提示、语音、错题复盘、小练习和自动 note：
使用简单英文，保留原课程 technical terms，只在难区分处加入短中文提示。
偏好跨设备、会话、模型持久；“这题用中文”只创建有范围的临时覆盖，不覆盖默认。
课程原文、用户原话、墨迹和源记录保持原语言。项目工程进度汇报可用中文，
不能据此改变产品教学语言。样例使用英文不是持久偏好功能已经实现的证据。

## 6. 验收与测量

验收定义使用主规格 §6 的 A30–A41，不另建一套相互偏离的验收编号。

**G7 做题过程与克制提示**：能力矩阵分别评估原 App 的视觉观察路径和自有画布的结构化路径，不要求所有外部 App 都通过；受限路径如实标注，P1 可在一条明确支持的路径完成闭环。P0 可先用合成样例测试协议、排序、缓存失效和教学策略；真实外部 App 与 Pencil 的验收必须单独在设备上执行。

首轮工程默认至少准备 30 组有标注的过程样例，包含快改、回退、分支、合理替代解法、错误理由碰巧正确、缺帧和未知动机。分别报告关键步骤保留率、顺序／分支准确率、误判正确解法、无依据诊断和提示越界。固定验收集中提前泄题、伪造步骤和错误标记独立掌握应为零；有限样本通过不等于模型在所有题目上都有保证。规则用程序验证，数学正确性与语义泄题用独立复核及真实用户试用验证，不能只让同一个模型自评。

实时性能沿用 §11 的测量原则，同时增加画面新鲜度和关键改写被保存的延迟；报告采集、同步、识别、推理、显示各段延迟和失败样例。进度动画不能算有效帮助。具体设备目标在 G7 首轮测量后确定，不将未测数字写成已达成。

没有 Mac／Xcode 和可操作设备路径时，平台结果仍须标为未编译或未真机验证；
网页测试、源代码阅读或平台文档均不能替代 A41。

## 7. 阶段衔接与职责

这组能力已进入核心产品范围。保留正在运行的 P0 任务，在安全边界衔接过程证据和帮助策略。以下是工程阶段默认，可依据验证调整，不是用户指定的固定排期；不得因此省略原 P1 看课、点读、记忆闭环。

1. **P0 增量：** 总工统一契约、G7 和追踪表；学习角色制作过程样例与提示越界评测；平台角色验证当前设备能取得什么过程证据。增加任务卡，不把已有验收描述改成已通过。
2. **P1 做出最小闭环：** 在至少一条明确支持的 iPad 路径中，实现一道真实题的开始、自主尝试、请求提示、复盘、保存和次日回查。若跨 App 过程不足，保留原页面看屏，并提供更可靠的作答画布入口；不能把用户所有学习迁移成上传 PDF 聊天。
3. **P2 提高教学效果：** 加入针对性微练习、跨题复习、帮助程度与独立掌握评价；完善外部笔记和复杂分支诊断。
4. **P3 按原规划扩大多设备：** 将同题过程与提示权限同步到 iPhone／Windows。Windows 的核心采集风险可在 P0 提前验证，但完整交付仍须单列，不能暗中假定已经可用。

协作分工：总工管理共享契约、接口和任务追踪；后台负责持久过程、版本与更正；学习角色负责提示策略、诊断和教学评测；iPad 与网页／Windows 角色负责各自真实采集及交互；QA 独立执行 A30–A41。模型选择不是此处主要缺口，先把共同证据和行为契约补齐。

当前调度、精确基线及依赖以[任务板](../tasks.md)为准；实施、编译、自动测试、
真实接通和真机验收分开报告。读取新规范不要求丢弃工作，允许先用
`git show <正式提交SHA>:docs/requirements/problem-solving-companion.md` 阅读，
再由总工协调保留本地改动的正常合并；不得 reset 或强制要求 ff-only。
