## Current platforms and complete delivery scope

Under the [desktop-first decision](intent-and-decisions.md#desktop-first), complete the required product on Windows and macOS before resuming native iPad/phone delivery. Execute each case's general behavior separately on both desktops. Explicitly defer and retain mobile-specific steps without counting them as passed or blocking independent desktop work. P0–P4 are functional slices, not permission to call a P0 probe or minimal P1 the complete desktop product: applicable Calendar, bCourses/Canvas, persistent URL, self-study, pregeneration/cache, teaching, long-term memory, supervision/reminders, budget, autonomous preparation and real work-agent requirements all remain required.

Native (existing role key `ios`) owns `apps/macos`; Web (`web`) owns `apps/windows` and webpages. Backend/Learning retain shared-service duties, Lead retains contracts and integration, and QA independently accepts each OS. Client ownership below follows that mapping; the retained `ios` key does not require iPad delivery first. P1/P2 desktop interaction and notes, P3 multi-source/autonomous behavior, and P4 work agents all belong to complete desktop delivery. P3-02 no longer defers the Windows/macOS original-screen pen layer until after core interaction.

An available Windows environment is not a feature pass; an interactive Mac route is still unconfirmed. When either desktop lacks actual test access, retain that platform blocker rather than closing it with the other desktop's results. Cloud macOS CI proves only builds/checks actually executed, not desktop capture, cross-app input, audio routing, real AI or destination import. Retain specific gaps in actual provider input, client integration and session/source-permission bootstrap. Sidecar is only a later Mac-app/Pencil-input candidate, not an overlay over arbitrary native iPad apps or a desktop prerequisite; it grants no purchase, account or paid-resource authority.

## Execution and reporting rules

- For every case, record the exact commit, device/OS, app and model versions, network, source authorization, actual samples and independently established reference answers, step records, failure examples, and artifact locations. Label real courses/accounts/devices separately from synthetic data; do not transfer results from one entry path to another platform. QA independently checks behavior, semantics, and original evidence on Windows and macOS separately; the lead determines phase integration status. Agreement between models does not substitute for evidence.
- Where a case spans phases, report completed slices and unfinished portions separately. P0 capability investigations and deterministic tests only prepare evidence. P1 still includes the calendar, persistent sources, real voice, local notes, and real single-problem loop required by the main specification; passing a minimal probe does not remove the remaining P2–P4 desktop goals. Retain native iPad/phone-specific variants as deferred rather than counting them as desktop passes.
- Reuse only the numerical targets in original main-specification §11. Unspecified long-session durations, capacity stress points, sampling strategies, prompt deduplication intervals, and evaluation cutoffs must be labeled **engineering defaults**. Explain the choice before execution and report actual distributions and failures; do not describe them as user-specified or achieved. Numerical targets remain initial engineering targets, not guarantees for arbitrary environments.
- A pass must satisfy both positive behavior and the case's negative cases, rather than merely checking fields or fixed text. Record unknown sources, unsupported platforms, and tests not run separately. Evidence-backed unsupported status is not a product-behavior PASS; retain the requirement gap and verified fallbacks.
- This document grants no new authority for external actions. Real provider calls, work-agent actions, and external writes use authorized connections and explicit task scope; verify budget controls before paid calls. Test records must not retain credentials or require the model's internal chain of thought. Summaries cannot replace original conversations, user ink, or sources; handle explicit deletion and revocation under the original specification.
- Skippable proactive teaching during ordinary course viewing, authorized supervision, companion memory across days, and autonomous preparation remain valid. The user instruction “让我自己试” (**English translation:** “Let me try on my own”) constrains assistance disclosure within the current problem-solving scope, rather than disabling proactive capabilities throughout the product. Within that scope, supervision, caches, voice, and added illustrations must not bypass the restriction. Explicit end, pause, and revocation requests still apply within their respective scopes.

## V-DailyResume — Return each day to the actual course

- **Links:** R01–R03, R06, R08–R10, R43–R45; existing A01–A03/A05/A06/A17/A23–A25, with handwriting and in-place paths additionally linked to A26–A28/A44–A46. Gates G1/G2/G4 remain separate and are not replaced by this case.

- **Prerequisites:** Operable real Windows and macOS systems, tested separately, an actual course and an independent self-study project. Retain the original iPad/native Canvas/Safari/Pencil device combination as a deferred variant; initial connection authorizations completed, a stable course URL saved, and Calendar/Canvas connected under actually available permissions. Retain specific unavailable-source states; do not substitute an empty project shell for a course.
- **Steps:** Enter the course and verify that Start clearly enables continuous whole-screen context, obtainable ink and relevant conversation for the selected authorized source. Circle a focus and receive a contextual explanation, silent by default, without another Ask press or typing; choose deeper directions and optionally follow up through text/real voice. Switch explicit talk/mute controls and check every actual spoken AI response against its floating captions. Drag the toolbar/captions across DPI settings, multiple monitors, monitor removal and position restoration. Save a local note with its source, close normally, and return next day through calendar and actual progress. Also run a self-study project without Canvas/a teacher/a formal syllabus, and separately simulate normal authorization refresh and revocation.
- **Success and negative cases:** Daily use does not require resending saved course links, material, or all background context; necessary system authorization confirmations are still shown honestly. Whole screen, obtainable ink and relevant conversation actually reach the model; circling highlights focus without losing the full screen or adding a typed-question prerequisite. Point reading does not speak by itself; mute/interruption leaves neither stale playback nor unauthorized captions, dragging sends no request, and restored controls remain in an available work area. Start/circling does not override exploration/full-solution limits. Actual microphone/system-playback gaps are not presented as support, and saving a recording is not required. After revocation, do not pretend the latest material remains readable. Merely completing “circle selection → fixture card → save → restart” is insufficient. If P1 notes contain only AI text, explicitly state that editable handwriting is not yet available; separately verify saving any enabled user ink. A canvas fallback does not pass R59/A44.
- **Artifacts:** First-day and next-day real-device operation records, source and note version comparisons, calendar instances and actual progress, refresh/revocation evidence, and lists of supported paths and unfinished items.
- **Status:** Not run/not accepted.
